추론 가중치는 고정되어 있습니다. 새 값이 들어올 때마다 이력과 예측을 갱신하고 기록을 누적합니다. 모델을 다시 학습하려면 운전 기록을 검토·라벨링하고 별도 검증을 거쳐야 합니다. 악화된 데이터를 자동으로 정상 학습에 섞지 않습니다.

한 번 튄 값은 이상 후보 점수에 반영하지만 곧바로 발전기 고장으로 단정하지 않습니다. 누락·역순·5초 이상 공백·장비 프로필 불일치·학습 조건 밖에서는 예측을 보류합니다. 유효한 다른 채널의 현재 긴급 기준 경보는 유지합니다.

예상 시간의 의미

화면의 예상 시간은 학습한 미래 계측값이 profile.json의 시연 기준에 도달할 때까지의 시간입니다. 예측 지점 사이를 보간하며 180초를 넘어서 외삽하지 않습니다. 이미 기준에 도달했다면 현재 도달 사실을 표시합니다.

예측 범위 안에 도달점이 없으면 시간을 만들지 않습니다. stop_eta_s와 failure_probability는 항상 null입니다. 실제 정지시점·잔여수명·고장확률을 학습한 자료가 없기 때문입니다.

그림의 음영은 별도 보정 데이터에서 구한 항목·시간별 절대 오차의 95백분위수를 적용한 구간입니다. 모든 미래 경로가 95% 확률로 들어온다는 보장이 아닙니다. 갑작스러운 부하 조작이나 정비는 발생 전 미리 알 수 없습니다.

학습 데이터와 확인된 성능

운전 한 회 전체를 기준으로 학습 108회 / 검증 27회 / 오차 보정 27회 / 시험 36회로 분리했습니다. 한 회는 20분, 표본 주기는 2초입니다. 겹치는 이력 구간이 학습·시험에 나뉘어 섞이지 않습니다. 150 epoch 중 검증 손실이 가장 낮은 39 epoch를 선택했습니다.

아래는 별도 시험 36회, 3,060개 이력 구간에서 120초 뒤 예측의 평균 절대 오차입니다. 모두 같은 합성 생성식 계열의 시험이며 실제 발전기 성능을 뜻하지 않습니다.

44개 항목×예측시간 조합 중 43개는 현재값 유지보다 MAE가 작았습니다. 배터리 180초 예측은 모델 0.0721 V, 현재값 유지 0.0641 V로 오히려 나빴습니다. 전체 수치는 모델 검증 화면과 reports/evaluation.json에 있습니다.

시험 운전의 정상·정상 부하 변화 8회에서는 점검/긴급 오경보가 없었고, 열화·회복 28회에서는 이상 시작 이후 점검이 발생했습니다. 최초 지속 기준 도달 예측 27건 중 24건이 그 뒤 180초 안에 실제 시연 기준에 도달했습니다. 냉각·연료 각 1건은 운전 종료까지 미도달, 유압 1건은 190초 후 도달했습니다. 경고 선행시간은 정상 모델 이탈 감지도 포함하므로 예측시간과 구분해야 합니다.

휴대폰 진동은 반복 기록의 32개 구간으로 학습하고 16개 구간으로 미확인 경계를 정했습니다. 별도 무작위 순서 기록의 48개 구간에서 RMS+진폭 변동 특징이 48/48, RMS만 사용한 모델이 36/48을 구분했습니다. 시험 기록은 1회이며, 48번의 독립 실험도 발전기 고장 정확도도 아닙니다.

가중치 JSON은 약 544 KB입니다. 현재 개발 컴퓨터의 NumPy 추론 중앙값은 약 0.249 ms였습니다. Arduino UNO Q에서 시간·메모리를 실측한 결과는 아직 없습니다.

계측 입력 연결

앱은 POST /api/telemetry에서 {"sample": {...}} 또는 {"samples": [{...}, ...]}를 받습니다. 한 요청당 1~100개, 시각 오름차순으로 보냅니다. 새 운전마다 run_id를 바꾸고, 같은 운전에서 단조 증가하는 초 단위 시각을 사용하세요.

{
  "sample": {
    "run_id": "demo-run-001", "timestamp_s": 0,
    "profile_id": "army-10kw-208v-predictive-demo-v1",
    "phase": "running", "data_source": "simulated_adapter",
    "coolant_c": 79.0, "oil_pressure_kgf_cm2": 3.2,
    "voltage_v": 208.0, "frequency_hz": 60.0, "engine_rpm": 1800,
    "current_a": 21.5, "current_b": 21.4, "current_c": 21.6,
    "battery_v": 13.8, "fuel_pct": 75, "fuel_pressure_bar": 2.4,
    "load_pct": 62, "ambient_c": 25
  }
}

이 예시는 한 표본의 형식입니다. 2초 간격의 연속 표본이 180초 이상 들어와야 예측합니다. 누락은 null로 표시하고 값을 만들어 채우지 마세요. 이 버전은 13개 입력 전체가 있어야 AI 예측을 진행합니다. 학습 부하 조건은 20~92%, 외기온은 11~37°C이며 실제 장비로의 일반화 범위를 의미하지 않습니다.

단위: 수온·외기온 °C, 윤활유압 kgf/cm², 출력 선간전압·배터리 V, 주파수 Hz, RPM, 상전류 A, 부하율·잔량 %, 연료압력 bar. 0.6 kgf/cm²를 0.6 bar로 바꾸면 안 됩니다. 모의 RPM은 주파수×30으로 생성되어 독립적인 증거가 아닙니다.

수신 결과: GET /api/state의 analysis에 상태, 이상 점수, 관측/예상값, 미래값, 기준 도달 후보, 점검 문구가 들어갑니다. 장비 통신 규격별 Modbus/CAN/시리얼 변환은 이 JSON 앞에 연결해야 합니다. 제어기 통신이 이미 검증됐다는 뜻은 아닙니다.

누적 기록: 서버의 recordings/에 원본 계측과 분석을 별도 JSONL로 저장합니다. 공통 record_id로 연결하고, 예측을 정답 라벨로 섞지 않습니다. 기록은 자동 재학습에 사용되지 않습니다. 20 MB 단위로 파일을 나누며 자동 삭제는 하지 않으므로 장기 운전 시 저장공간을 관리하세요.

습도·표면 온도·실제 보호장치 신호는 이번 학습 입력에 포함되지 않았습니다. 연료압력·연료잔량·부하율은 추가 계측을 가정한 시연 항목이며 군 필수 계기 항목이라고 단정하지 않습니다.

기존 진동 센서와 연결

진동 센서 화면에서 기본값은 실측 기록 재생입니다. 발전기 모의 열화와 별도로 녹화된 휴대폰 진동 기록이며, 둘이 같은 장비에서 동시에 측정됐다는 의미가 아닙니다.

이미 구현된 센서 수집 서버가 http://127.0.0.1:8765/api/samples?after=...를 제공하면 실시간 입력을 선택할 수 있습니다. 연결 버튼에서 포트와 센서 부착·축·단위 조건을 확인합니다. 서버를 자동으로 시작하거나 기존 펌웨어를 변경하지는 않습니다.

{"samples":[
  {"id":1,"seq":1,"elapsed_s":0.0048,"ax_g":0.01,"ay_g":0.00,"az_g":1.00}
],"status":{"connected":true,"fresh":true,"meta":{"accel_range_g":2}}}

위는 형식 예시입니다. 약 209 Hz의 실제 가속도 표본이 2초 이상 필요합니다. g 단위의 3축 가속도에서 축별 평균을 제거해 벡터 RMS와 100 ms 진폭 변동을 산출합니다. 짧은 기록·표본 공백·포화·미수신·부착 조건 미확인에서는 판정을 보류합니다. full-scale이 없으면 포화 검증을 못했다는 품질 메모를 남깁니다.

현재 학습 라벨의 ‘강한 연속 진동’은 점점 커지는 고장 진동이 아닙니다. 증가 추이는 별도의 12초 관측 규칙으로 표시합니다. 베어링 결함·축 정렬 불량처럼 실제 고장 종류를 학습하려면 해당 발전기의 실측 라벨 데이터가 추가로 필요합니다.

Arduino UNO Q 적용과 재학습

이 실행본은 UNO Q의 Linux 측에서 Python + NumPy로 추론하는 구성입니다. MCU용 펌웨어 또는 TFLite Micro 바이너리는 아닙니다. 폴더를 복사하고 가상환경에서 NumPy를 설치한 뒤 같은 server.py 또는 replay.py를 실행하는 형태로 연결합니다. 보드에서는 아직 실행 검증하지 않았습니다.

python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 server.py --port 8768

서버는 해당 장치의 127.0.0.1에만 열립니다. PC 브라우저에서 보려면 장치 계정과 주소를 사용해 SSH 터널을 열 수 있습니다: ssh -L 8768:127.0.0.1:8768 사용자@보드주소. 사용 중인 포트와 장치 접속 환경에 맞춰 변경하세요.

화면 없이 연속 추론

python3 replay.py --scenario cooling_decline --events-only
python3 replay.py --input data/telemetry-test.jsonl.gz --output result.jsonl

동일 합성 데이터 실험을 다시 학습

python3 -m pip install -r requirements-training.txt
python3 train.py
python3 vibration.py --train
python3 verify_scenarios.py
python3 -m unittest discover -s tests -v

학습은 개발 PC에서 하고 생성된 models/ 파일을 보드로 옮기는 구성을 권합니다. train.py는 제공된 합성 시나리오를 재생성하며 models/·data/·reports/의 해당 결과를 덮어씁니다. 중요한 실험 결과는 먼저 복사하세요. 운전 기록을 넣으면 자동으로 올바른 모델이 만들어지는 범용 학습기는 아닙니다.

실측 모델로 전환할 때는 정상/부하 변화/고장/센서 오류를 구분하고, 부착 위치·샘플링·단위·실제 경보 시각·정비 결과를 함께 기록해야 합니다. 운전 한 회 또는 장비 단위로 시험 데이터를 분리하고, 정상 오경보·고장 탐지 지연·미래 예측 오차를 다시 확인한 뒤 가중치를 교체하세요.
