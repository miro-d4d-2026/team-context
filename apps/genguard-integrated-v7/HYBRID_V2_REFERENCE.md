# GenGuard — 실제 IMU + 모의 발전기 합동 시연 v2

**진동은 UNO Q에 연결된 IMU에서 받고, 수온·유압 등은 웹에서 조절합니다. 분석과 진동 기준 학습은 API 서버를 실행하는 장치에서 수행합니다.** API를 UNO Q Linux에서 실행하면 온디바이스 분석입니다. 인터넷 AI API를 호출하지 않습니다.

```text
실제 IMU → 기존 UNO Q gateway → 2초 특징 추출 → 현재 부착 상태의 진동 모델 ┐
                                                                       ├→ 상태·근거·점검 권고 → 웹
웹 수온·유압·RPM 등 모의 값 → 발전기 모의 모델 + 고정 경보 규칙          ┘
```

화면에는 **실제 IMU / IMU 기록 재생 / 웹 입력·모의** 출처를 구분합니다. 웹에서는 실제 진동값을 덮어쓸 수 없습니다. `model_bundle`의 0.045g 모의 진동 기준은 실측 진동에 적용하지 않습니다.

## 빠른 시작: UNO Q 터미널 두 개 + Mac 브라우저

기존에 IMU 데이터를 수집하던 UNO Q gateway는 계속 실행해 둡니다. 이 패키지에는 MCU 펌웨어가 없으며, 이미 동작하는 gateway의 TCP `127.0.0.1:9877`을 추가 구독합니다. 현재 gateway의 실제 포트·형식이 다른 경우 [어댑터 설명](adapter/README.md)을 확인하세요.

ZIP 전체를 UNO Q Linux의 새 폴더에 풉니다. 아래 `/home/arduino/genguard-unoq-hybrid-v2`는 예시 경로입니다. v1의 `state/`를 복사하지 않습니다.

**터미널 1 — 설치 및 분석 API 실행**

필요 환경: Python 3.10 이상, NumPy, Node.js 18 이상. Python/venv·Node가 없으면 보드 OS의 패키지 관리 방법으로 먼저 준비합니다.

```sh
cd /home/arduino/genguard-unoq-hybrid-v2
python3 --version
node --version
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
export OPENBLAS_NUM_THREADS=1
export OMP_NUM_THREADS=1

# 팀이 정한 토큰으로 변경: 16자 이상 ASCII, 공백 없이
export GENGUARD_API_TOKEN='replace-with-your-team-token-2026'
python server.py --host 0.0.0.0 --port 9879
```

**터미널 2 — 실제 IMU 어댑터 실행**

```sh
cd /home/arduino/genguard-unoq-hybrid-v2
export OPENBLAS_NUM_THREADS=1
export OMP_NUM_THREADS=1
export GENGUARD_API_TOKEN='replace-with-your-team-token-2026'
.venv/bin/python -m adapter.imu_to_api \
  --installation phone-mount-001 \
  --api-url http://127.0.0.1:9879
```

두 터미널의 토큰은 같아야 합니다. `--installation`은 부착 위치·방향·받침을 식별하는 이름이며 다시 붙였다면 새 이름을 사용합니다. 어댑터에 `--csv`를 주지 않은 기본 모드가 실제 gateway 구독입니다.

**Mac 브라우저**

1. Mac과 UNO Q를 같은 로컬 네트워크에 연결합니다.
2. `http://UNO_Q_IP:9879`를 엽니다. `UNO_Q_IP`는 실제 보드 주소입니다.
3. 서버와 같은 토큰을 입력하고 **연결 · 시험 시작**을 누릅니다.
4. 진동 카드의 **실제 IMU** 출처, 2초마다 바뀌는 수집 창 ID, 수신 상태를 확인합니다.
5. 아이폰 진동 앱에서 **기준 진동을 자동 반복**합니다. IMU·아이폰·받침을 고정하고 손을 뗍니다.
6. “현재 진동과 부착 상태를 정상 기준으로 사용합니다”에 체크하고 **정상 기준 수집 시작**을 누릅니다.
7. 약 30초 동안 진동을 유지합니다. **15/15·기준 등록됨**가 된 뒤 **2초마다 자동 분석**을 켭니다.

토큰은 URL이나 공개 저장소에 넣지 않습니다. 이 서버는 신뢰하는 해커톤 로컬 네트워크에서 사용하는 HTTP 시제품입니다.

## 시연 순서

| 단계 | 사용자가 하는 일 | 기대 동작 |
| --- | --- | --- |
| 정상 | 학습 때의 기준 진동 유지 + 웹 정상 기본값 | 각 비교 기준 내, 새 경고 없음 |
| 진동 변화 | 웹 값은 유지하고 **아이폰 앱**에서 강도 증가 또는 간헐 진동 선택 | 실측 진동의 변화 점수·근거 표시, 서로 다른 이상 창 3개에서 지속되면 점검 알림 |
| 모의 수온 변화 | 아이폰 기준 진동 유지 + 웹 **수온 상승** | 수온의 모의 출처 표시, 발전기 모델·고정 규칙으로 판단 |
| 모의 복합 변화 | 웹 **범위 안 복합 변화**: 수온 89℃·유압 2.6kgf/cm² | 고정 한계 이내지만 모의 정상 패턴과 다른 조합을 탐지 |
| 긴급 규칙 | 수온을 직접 100℃로 설정 | 고정 규칙의 긴급 참고 경보. 진동 학습 여부와 별개로 동작 |
| 수신 중단 | 어댑터 종료 또는 센서 연결 중단 | 5초를 넘긴 실측값은 오래된 값으로 표시, 진동 판단 불가 |

프리셋은 모의 입력만 바꿉니다. 자동 분석을 켜거나 **한 번 분석**으로 전송해야 적용됩니다. 진동값을 웹 입력으로 임의 변경하는 프리셋은 없습니다. 진동 변화의 실제 탐지 여부는 부착과 진동원에 따라 달라지므로 발표 전에 해당 상태에서 확인하세요.

센서가 끊겼더라도 수온 등의 유효한 모의 긴급 경보는 유지됩니다. 이때 전체 상태와 별도로 **진동 판단 불가**를 표시합니다. API 응답 자체가 5초 넘게 끊기면 화면의 마지막 정상 결과를 현재 정상으로 유지하지 않습니다.

## 무엇을 학습하고 판단하나

| 영역 | 입력·기준 | 수행하는 일 |
| --- | --- | --- |
| 실측 진동 학습 | 2초 창 RMS(g)·간헐성 CV(무차원), 현재 부착 상태에서 확인한 정상 15창 | 처음 10창으로 로그 특징 평균·공분산 학습, 다음 5창으로 정상 일관성 확인 |
| 실측 진동 판단 | 새로운 고유 IMU 창 + 위 학습 기준 | 기준 대비 변화 점수. 3개의 서로 다른 이상 창이 지속될 때 점검 알림 |
| 발전기 모의 모델 | RPM·수온·유압·선간전압, 부하율·주변온도 조건 | 전달된 회귀 모델에서 발전기 4채널의 주변 공분산을 분리해 조건 대비 변화 분석 |
| 고정 규칙 | 모의 수온·유압·RPM·전압·주파수·연료·배터리 등 | 준비된 시연 기준과 지속 조건으로 경고 판단 |
| 합동 결과 | 위 결과와 각 입력의 품질·출처 | 현재 상태, 변화 근거, 점검 항목, 새로운 경고 이벤트 반환 |

진동 학습은 **실제 데이터를 이용한 통계적 머신러닝**입니다. 단순히 과거 사례를 검색하는 방식은 아닙니다. RMS는 축별 평균을 제거한 3축 진동 강도이고, CV는 100ms 구간의 RMS 변화 정도입니다. 계산 정의와 품질 검사는 [어댑터 설명](adapter/README.md)에 있습니다.

학습 중 진동이 너무 작거나 불안정하거나, 중복·누락·불량 창이 있거나, 보류한 정상 5창이 학습 기준과 크게 다르면 등록에 실패합니다. 정상 기준은 사용자가 “이 진동을 정상 기준으로 사용한다”고 선택한 데이터입니다. 실제 발전기 건전성을 확인한 결과가 아닙니다.

발전기 쪽은 `context-ridge-residual-covariance/1` 모델에서 실제 진동과 섞으면 안 되는 **모의 진동 2항목을 제외**합니다. 6채널 precision에서 4×4만 잘라 쓰지 않고 전체 공분산을 복원한 뒤 발전기 4채널 주변 공분산을 선택합니다. 알고리즘 표시는 `context-ridge-residual-covariance-marginal-4/1`입니다. 임계점수 2는 새 4채널 시연 설정이며 **원래 6채널 모델의 검증 성능을 그대로 승계하지 않습니다.**

이 시연은 **실측 진동과 모의 발전기 값의 독립 분석 결과를 결합**합니다. 실제 발전기의 수온·유압·진동 사이 고장 상관관계를 함께 학습한 것으로 발표하지 않습니다. 모델 점수는 고장 확률·잔여수명이 아닙니다. 점검 문장은 변화 근거와 준비된 점검표의 연결입니다.

## 상태 저장과 재학습

- 사용자가 기준 수집을 시작할 때만 IMU 기준을 학습합니다. 경고가 났다고 이상 데이터를 정상에 자동 편입하지 않습니다.
- 모델 원본은 `model_bundle/`에 보존하고, 수집 창·기준·분석 이력은 이 서버의 `state/bridge.sqlite`에 저장합니다.
- 센서 스트림, 부착 ID, 출력률, 측정 범위, 출처가 바뀌면 기존 기준을 무효화합니다. 기준 진동을 유지한 상태에서 다시 등록합니다.
- API 서버 재시작 후에는 새 IMU 수신과 기준 등록이 필요합니다. 저장된 기준을 확인 없이 자동 활성화하지 않습니다.
- 어댑터는 단절이나 전송 실패 시 종료합니다. 문제를 확인하고 다시 실행하면 새 스트림이 되므로 기준을 새로 등록합니다.
- 웹 분석 요청 재전송은 같은 순번·내용에 한해 중복 처리합니다. 같은 센서 창을 여러 번 조회해도 진동 지속 횟수를 늘리지 않습니다.

## 기존 홈페이지에 연결

[MIRO_HANDOFF.md](MIRO_HANDOFF.md)의 코드와 필드 매핑을 사용하세요. 웹에 복사할 파일은 `web/client.mjs`입니다. 기존 계측 UI와 그래프를 유지하고 API 응답을 연결할 수 있습니다.

별도 웹 개발 서버에서 호출한다면 API 시작 시 실제 브라우저 origin을 허용합니다.

```sh
python server.py --host 0.0.0.0 --port 9879 \
  --allow-origin http://localhost:5173
```

`localhost`, `127.0.0.1`, IP는 서로 다른 origin입니다. HTTPS 웹에서 HTTP UNO Q를 직접 호출하면 브라우저가 차단할 수 있으므로, 먼저 UNO Q가 제공하는 동봉 화면으로 연결을 검증합니다.

## 보드가 없는 개발 환경

기록 CSV를 재생할 수 있으나 화면 출처는 **IMU 기록 재생**입니다. 명령과 CSV 필수 항목은 [어댑터 설명](adapter/README.md)에 있습니다. 기록을 현재 실측으로 표시하지 않습니다. 기본적으로 공개 데이터셋이나 팀의 원시 실측 CSV를 이 ZIP에 다시 포함하지 않습니다.

```sh
.venv/bin/python -m adapter.imu_to_api \
  --installation recorded-phone-mount-001 \
  --csv /실측기록경로/20261010T104429-70687ed6.csv \
  --recorded-odr-hz 208 --recorded-range-g 4
```

## 확인 및 파일 구성

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python -m unittest discover -v
node --test web/test_client.mjs web/test_demo.mjs
```

자동 테스트는 소프트웨어 동작과 입력 품질·출처 처리를 검증합니다. **이 패키지를 실제 UNO Q와 현재 부착 IMU에 설치해 실행한 통합 확인은 별도로 필요합니다.** Mac에서 API를 실행했다면 모델도 Mac에서 실행된 것입니다. 보드 설치 후 위 시연 순서로 실제 수신·기준 학습·변화·단절을 확인해야 합니다.
