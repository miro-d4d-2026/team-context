## 진동에 맞춰 자동으로 움직이는 모의 발전기

**IMU 연결 → 진동에 맞춰 모의 운전**을 켭니다. 진동만 실측이고 나머지 계측은 `진동 연동 모의`로 표시합니다.

| 아이폰 진동 | 모의 발전기 동작 |
|---|---|
| 정지 | RPM·전압·부하 0, 수온은 주변온도로 서서히 냉각 |
| 기준 진동 | 2개 센서 창 확인 → 약8초 RPM 상승 → 전압 형성 → 부하 상승 → 수온 점진 상승 |
| 강도 증가 | 실제 진동 기준과 비교해 점검 권고, 모의 RPM은 유지 |
| 간헐 진동 | 불규칙한 실측 진동을 바탕으로 모의 RPM·전압·부하가 흔들리는 구동 불안정 시연 |
| 센서 미수신 | 모의 진행 보류·그래프 공백. 정지한 것으로 단정하지 않음 |

수온은 약90초의 시정수로 운전 목표80°C에 접근하고, 정지 후 약60초의 시정수로28.5°C에 접근합니다. 실제 발전기의 열 모델이 아니라 행사장에서 변화를 볼 수 있도록 정한 시연 가정입니다. 정상 진동을 학습하면 부착 기준을 활용하고, 미등록 때는 진동 활성화에만 가정값을 씁니다. 시작은 max(0.025g, 정상기준×0.45), 정지는 max(0.015g, 정상기준×0.30)이며 서로 다른 2개 센서 창에서 확인합니다. 실제 정지 잔진동0.0049~0.010g을 반영한 이번 아이폰 부착 실험용 가정입니다. 미등록 상태에서 AI가 정상 학습을 마친 것처럼 표시하지 않습니다.

수온·유압의 이전 점검 AI 비교는 **모의 운전** 모드에서 확인합니다. 진동 연동 모의는 시동·정지의 화면 시연이며 생성값을 정상 발전기 학습 이력에 넣지 않습니다. 수동 값을 바꾸려면 연동을 끕니다. 현재 UNO Q 시작 스크립트는 같은 설치 조건에서 기존 기준을 복원하고 연동을 켭니다. 부착 조건이 달라졌다면 기준을 새로 등록합니다.

## 지금 아이폰으로 시연하기

웹 서버와 USB 수신기가 켜진 상태에서 `http://127.0.0.1:9883`의 **IMU 연결**을 선택합니다.

1. 아이폰에 IMU를 고정합니다. 아이폰은 진동을 만들고, UNO Q의 IMU가 진동을 측정합니다.
2. 아이폰 앱의 **반복 설정 → 종류별 측정 구간20초 / 구간 사이 휴식0초 / 반복 횟수10회**로 설정합니다.
3. **진동 패턴 → 기준 진동**을 누릅니다. 무작위 평가나 학습용 일괄 수집은 이번 정상 기준 등록에 사용하지 않습니다.
4. 웹에서 현재 진동을 정상 기준으로 등록할 체크박스를 확인하고 **정상 진동30초 수집**을 누릅니다. 15/15와 정상 기준 등록됨을 확인할 때까지 그대로 유지합니다.
5. 그다음 아이폰의 **정지 → 강도 증가**로 전환합니다. 2초 단위 RMS와 기준 대비 배율이 커지고, 서로 다른 이상 창3개가 이어지면 점검 권고가 표시됩니다.
6. **정지 → 기준 진동**으로 되돌려 정상 복귀를 확인합니다.

기준 수집 중에 일반/강함/무작위를 섞으면 등록이 거절될 수 있습니다. 현재 실제센서와 모의 발전기값은 출처를 구분합니다. 과거아이폰4종분류모델은 기록재생에, 새실측은 지금부착상태의30초정상기준과비교하는데사용합니다.

**현재 실행 위치:** 센서 수집·특징 계산·모델 판단·웹 API는 모두 UNO Q에서 실행됩니다. 아래 Mac 실행 절차는 개발용입니다. 현재 보드 실행법은 deployment/UNO_Q_RUNBOOK.md를 따릅니다. 연결된 보드에서 분석까지 실행한 것은 아닙니다. 보드 배포에 남은 실행환경 조건은 [USB_CONNECTION.md](USB_CONNECTION.md)에 명시했습니다.

## 다시 실행하는 두 파일

- `GenGuard_웹_시작.command`: 로컬웹서버 시작.
- `adapter/USB_IMU_연결.command`: 기존 UNO Q gateway와 USB 터널을 연결하고 실측 진동을 웹으로 전달.

둘 다 켠 상태를 유지합니다. 최초 사용환경에서는 아래 Python 의존성과 USB_CONNECTION의 ADB 준비가 필요합니다. 서버·수신기가 이미 실행 중이면 중복 실행하지 않습니다. 수신이 끊기거나 서버가 재시작되면 새 기준을 등록합니다.


수온·유압·진동을 모두 현재값 차이로 비교하던 화면을 수정했습니다. **수온은 구간별 상승 속도, 유압은 예열 중 하락 속도와 구간 말 압력, 진동은 평소 크기와 갑작스러운 변화**를 각각 판단합니다. 과열·저유압·과속의 절대 보호 참고값은 독립적으로 유지합니다.

## 바로 실행

Python 3.10 이상과 Node.js 18 이상을 사용합니다. ZIP 전체를 새 폴더에 풉니다.

```sh
cd genguard-integrated-v7
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
export OPENBLAS_NUM_THREADS=1
export OMP_NUM_THREADS=1
python server.py --port 9883
```

브라우저에서 `http://127.0.0.1:9883`를 엽니다. 기존 서버가 같은 포트를 사용 중이면 해당 서버를 종료하거나 다른 포트를 지정하세요. 모델 계산은 서버가 실행되는 기기에서 이루어집니다. 이번 검증은 Mac에서 수행했으며 UNO Q 실행 성능은 아직 측정하지 않았습니다.

## 세 페이지

- **대시보드 `/`**: 상태 요약, 12개 주요 계측, 짧은 운전 추이, 먼저 확인할 항목. 본문과 글자 크기를 줄여 한 화면에 배치했습니다.
- **이전 점검과 비교 `/comparison`**: 같은 경과 시간의 이전/현재 곡선, 5분 구간별 변화량·상승률, 모델 근거. 아이폰 실측 기록 재생도 이 화면에 있습니다.
- **점검 기록 `/records`**: 기록 저장, 정상 승인, 재학습, 전체 계측·수동 점검 항목.

메뉴가 분리되어 다른 페이지의 긴 표·설정은 대시보드에 나오지 않습니다. 세부 가정과 모델 정보는 접힌 설명에 두었습니다.

## 먼저 확인할 시연

1. 기본 화면은 **운전 10분, 수온 80°C**입니다. 5–10분에 60→80°C, 즉 **+20°C / 4°C·분⁻¹**으로 올랐습니다. 정상 이력의 같은 구간은 약+8°C / 1.6°C·분⁻¹이므로 절대 고온 기준 전에도 점검 권고가 뜹니다.
2. **운전 값 변경 → 평소 운전 → 운전 기록 분석 → 20분**: 50→60→68→73→78°C로 온도가 계속 올라가도 정상 상승 흐름으로 판단합니다.
3. **유압 급하락**: 예열에 따른 정상 감소보다 빠른 하락과 낮은 압력을 함께 확인합니다. **진동 증가**는 같은 부착 조건의 정상 크기·직전 구간 대비 비율로 판단합니다.
4. **현재 운전 시점**을 5분으로 바꾸면 10분 이후에 입력한 이상값은 아직 판단하거나 그리지 않습니다. 저장도 선택한 시점까지의 관측값만 합니다.
5. **점검 기록 → 현재 점검 저장**: 기본은 관찰 기록입니다. 정상으로 확인하고 분석도 정상인 기록만 정상 학습 후보가 됩니다. **정상 기록으로 다시 학습**을 눌러 갱신합니다. 이상 기록을 자동으로 정상 학습에 넣지 않습니다.

## README보다 항목이 적었던 이유와 반영 범위

이전 화면은 모델 검증을 위해 수온·유압·진동 세 가지를 먼저 연결한 버전이었습니다. 이번에는 고정했던 원래 명세의 **표시 항목 25개 + 수동 점검 9개**를 복원했습니다. 상세표는 [FIELDS_AND_METHODS.md](FIELDS_AND_METHODS.md)에 있습니다.

대시보드에는 수온·유압·진동·RPM·전압·주파수·부하율·상전류·배터리·연료·주변 온도·습도 12개를 표시합니다. 그 밖의 역률·누적 시간·상별 전류·예열·보호 신호·차단기 상태·표면 온도·오일 온도 등은 전체 항목표에서 확인합니다. 없는 계측은 미연결, 수동 점검은 미확인입니다.

**모든 항목을 억지로 같은 AI에 넣지는 않습니다.** 수온·유압·진동은 이력 학습, RPM·전압·부하·배터리·연료는 기준 확인, 습도는 환경 참고, 보호 신호는 장비가 제공할 때의 상태 확인입니다. 지금의 주파수·전류·출력은 모의 입력에서 계산한 값으로 표시하며 실제 독립 센서값처럼 학습하지 않습니다.

## 학습과 정상 기준

`operation-phase-context-ridge/1`은 운전 단계마다 부하·외기온·RPM·초기 수온과 정상 변화의 관계를 학습하는 작은 Ridge 회귀 모델입니다. 초기 정상 운전 8회, 각5시점, 총32구간은 **합성 데이터**입니다. 사용자 예시를 동작하는 모델과 화면으로 구현하기 위한 자료이며 실제 발전기 검증 자료가 아닙니다.

- 같은 장비·출처에서 과거 정상 확인된 서로 다른 기록만 사용합니다.
- 부하±5%p, 외기온±5°C, RPM±50, 초기 수온±5°C 범위에서 같은 시간 구간을 비교합니다.
- 진동은 부착 위치·수집 설정도 일치해야 합니다.
- 현재 운전·미래값·미승인/이상 이력은 학습에서 제외합니다. 3회 이상의 적합한 정상 이력이 없으면 비교 보류입니다.
- 현재 버전은 **시동부터 연속된 5분 간격 관측값**을 사용합니다. 임의 간격이나 누락을 정상값으로 보간하지 않습니다.
- 허용 편차는 학습 잔차와 시연 가정값을 함께 사용합니다. 상세 수치는 [OPERATION_MODEL.md](OPERATION_MODEL.md)에 있습니다.
- 고정 보호값 확인은 현재 시점의 참고 판단입니다. 5분 점검점으로 5초 연속 초과를 검증했다고 주장하지 않습니다. 실제 발전기의 보호기를 제어하지 않습니다.

`operation_artifacts/`에 학습 계수, 입력 이력, 시나리오, 독립 난수 합성100개 검증 결과를 넣었습니다. `state/bridge.sqlite`에는 저장한 점검이 남습니다. 재학습 계수는 `state/operation-model.json`에 저장하며 서버 재시작 시 저장된 정상 기록을 읽어 조건별 모델을 구성합니다. 원인 후보와 점검 문구는 규칙으로 연결하며 고장 부위를 확정하거나 RUL을 산출하지 않습니다.

## 실측 진동과 모의 운전

- **모의 운전**: 세 가지 이력을 모두 모의 정상 기록과 비교합니다.
- **실측 기록**: 아이폰 반복 테스트32창으로 학습하고16창으로 수용 거리를 보정한 패턴 모델이 랜덤 기록48창을 분류합니다. 진동은 실측 기록 재생, 수온·유압 등은 모의로 구분합니다. `/comparison`에서 재생합니다.
- **IMU 연결**: 현재 실제 센서 창을 등록한 부착 기준과 비교합니다. 진동은 웹에서 수정할 수 없습니다. 센서가 끊기면 모의 진동으로 대체하지 않습니다. 기준 등록은 대시보드에서 바로 할 수 있고 상세 수집 정보는 `/lab`에서 확인합니다.

실측 진동은 가상 발전기의 시계열과 연결해 학습하지 않습니다. 혼합 모드에서는 발전기 점검으로 저장·재학습할 수 없습니다. 실제 이전 운전의 진동 추이 비교에는 실측 운전 조건과 같은 설치의 정상 이력이 필요합니다. 아이폰 패턴 분류의 데이터와 한계는 [VIBRATION_MODEL.md](VIBRATION_MODEL.md)를 참고하세요.

## UNO Q와 기존 웹 연결

폴더 전체를 UNO Q Linux에 복사하고 같은 명령을 사용합니다. LAN으로 열 때는 토큰이 필요합니다.

```sh
export GENGUARD_API_TOKEN='replace-with-your-team-token-2026'
```
