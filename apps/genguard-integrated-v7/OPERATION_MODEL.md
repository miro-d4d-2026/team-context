# 운전 구간별 상태 변화 분석 v6

온도·유압·진동을 같은 방식으로 비교하지 않습니다. `operation_model.OperationAnalyzer`는 **이전 정상 운전의 같은 시간 구간**과 현재 관측된 구간을 비교합니다. 현재값 하나가 아니라 0·5·10·15·20분 기록을 사용합니다.

## 무엇을 학습하는가

| 항목 | 학습 대상 | 이번 운전에서 판단하는 것 |
|---|---|---|
| 냉각수 온도 | 각 5분 구간의 정상 온도 상승 속도 | 현재 구간의 °C/분이 같은 단계의 기대치보다 빠른가 |
| 윤활유 압력 | 예열 중 정상 압력 하락 속도와 구간 말 압력 | 정상적인 예열 하락보다 빠른 급락 또는 평소보다 낮거나 높은 압력인가 |
| 진동 RMS | 같은 위치·수집 설정에서 구간 말 진동 크기 | 평소 진동 대비 크기 변화 또는 직전 구간에서 갑자기 증가·감소했는가 |

수온 모델은 `50→60→68→73→78°C`를 정상 시나리오로 학습합니다. 구간 상승량은 `+10,+8,+5,+5°C`, 속도는 `2,1.6,1,1°C/분`입니다. `50→60→80→85→90°C`는 5–10분에서 `+20°C / 4°C/분`으로 점검을 권고합니다. 마지막 구간의 상승 속도가 다시 평소와 비슷해져도 앞선 이상 구간을 지우지 않고, 회복 여부와 함께 보여줍니다.

수온이 내려가는 경우는 이 버전에서 과열 점검 권고로 만들지 않습니다. 절대 고온·저유압·과속 등의 보호 참조 기준은 서비스의 독립 규칙이 담당합니다. 모델의 “평소 변화” 판정은 그 보호 경보를 취소하지 않습니다.

## 모델과 데이터 범위

- 알고리즘: `operation-phase-context-ridge/1`. 각 운전 단계마다 부하·외기온·RPM·초기 수온을 입력으로 사용하는 작은 Ridge 회귀 모델입니다.
- 데이터: 과거 정상 운전 **8회, 각 5개 시점, 총 32개 운전 구간**의 합성 데이터입니다. 실제 발전기 이력이 아닙니다.
- 조건: 부하 차이 5%p, 외기온 5°C, RPM 50, 초기 수온 5°C 이내의 이전 정상 기록만 사용합니다. 서로 다른 모의/실측 출처를 섞지 않습니다.
- 진동 추가 조건: 부착 위치, 수집 속도, RMS 창 길이, DC 제거, 특징량 버전이 같아야 합니다.
- 현재 운전, 미래 기록, 정상 미확인 기록은 학습에서 제외합니다. 똑같은 구간을 복사해 정상 이력 수를 늘릴 수 없습니다.
- 최소 3회의 서로 다른 정상 기록이 없으면 “정상” 대신 비교 보류입니다.
- 임의의 길이/누락 구간을 보간하지 않습니다. 현재 시점까지의 `0,300,600…초` 접두 기록만 평가합니다. 5분 계측 프로필은 초 단위 과도 현상을 검증하지 않습니다.

## 탐지 허용차의 출처

아래는 해커톤 동작 확인을 위해 정한 **가정값**입니다. 제조사 경보 기준 또는 통계적으로 검증된 고장 확률이 아닙니다.

| 항목 | 최소 차이 / 허용 폭 |
|---|---|
| 냉각수 상승 속도 | 기대치보다 +0.5°C/분 이상 빠름 |
| 유압 변화 속도 | 기대치보다 -0.035kgf/cm²/분 이상 빠르게 하락 |
| 구간 말 유압 | 기대치 대비 ±0.25kgf/cm² 초과 |
| 구간 말 진동 RMS | 기대치 대비 1.35배 초과 또는 1/1.35배 미만 |
| 직전 구간 대비 진동 | 1.5배 초과 또는 1/1.5배 미만 |

실제 적용 허용 폭은 위 가정값과 학습 잔차 표준편차의 3배 중 큰 값입니다. 진동은 로그 공간에서 학습합니다. 진동 감소는 운전 상태·부착 상태를 확인하라는 뜻이며 고장을 확정하지 않습니다.

## 재현 및 실행

```sh
python3 -m unittest test_operation_model -v
python3 train_operation.py
```

```python
from operation_fixtures import seed_records, seed_current
from operation_model import OperationAnalyzer

analyzer = OperationAnalyzer(seed_records())
result = analyzer.analyze(seed_current())
artifact = analyzer.export_model()  # 방금 분석에 사용한 계수와 학습 기록 ID
```

`operation_artifacts/model.json`에는 학습 계수, 정규화 정보, 구간별 임계 차이, 학습 기록 ID가 있습니다. `normal-records.json`은 입력 이력, `scenarios.json`은 조작 가능한 모의 운전, `example-results.json`은 구간별 분석 결과, `validation.json`은 별도 난수로 만든 합성 시나리오 100개 검증 결과입니다. 이 100개는 실제 고장 100건 또는 발전기 정확도 평가가 아닙니다.

## API 반환값

`analyze(current_run, reference_id=None)`는 `channels`에 항목별 판단을 반환합니다. 각 `intervals` 행은 `start_s`, `end_s`, `observed_delta`, `expected_delta`, `observed_rate`, `expected_rate`, `state`를 가집니다. 진동의 rate는 `null`이며 대신 `change_ratio`, `step_ratio`, `model_expected`를 사용합니다.

채널 상단의 `current`, `interval`, `observed_rate`는 마지막 관측 구간입니다. 앞선 이상 구간 때문에 채널이 점검 상태일 수 있으므로 점검 근거는 `worst_interval`과 `summary`를 함께 표시해야 합니다. 누락 항목은 `unavailable`, 나머지 유효 항목은 독립적으로 판단합니다.
