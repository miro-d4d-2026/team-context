# GenGuard 현재 상태 · 자동 학습 · 2026-10-11

**사람은 정상·비정상만 검토하고, 시스템이 운전 회차를 나누어 학습·성능 평가를 진행합니다.** 사용 순서는 [자동 학습 안내](AUTO_LEARNING_GUIDE.md)를 따릅니다.

- 기존 실측 IMU 수신·정상 기준·진동 연동 모의 계측 유지.
- 학습·보정·검증 역할 선택 제거. 동일 장비·설치·출처의 기록 묶음과 `AI 학습` 버튼으로 통합.
- 정상만 충분하면 정상 모델, 두 종류의 사례가 충분하면 분류기도 학습.
- 재학습은 누적 승인 기록으로 같은 절차를 다시 실행. 과거 평가 회차를 학습에 섞지 않음.
- 평가 수치와 같은 평가 기록에서의 기존 모델 비교 제공. 비정상 자료가 없는 평가에는 비정상 검출률을 표시하지 않음.
- 후보 통과와 적용은 별개. `새 모델 적용` 후 다음 운전부터 사용하며 기존 보고서는 보존.

## 검증

- 전체 Python **270개 통과**: `verification/auto-learning-python.log`.
- 전체 JavaScript **164개 통과**: `verification/auto-learning-javascript.log`.
- 격리된 합성 기록으로 초기 정상 학습 → 정상 기록 추가 재학습 → 비정상 기록 추가·분류기 학습 → 명시적 적용 → 새 운전 판단 → 재시작 후 보고서 보존을 확인. `verification/auto-learning-host.json`.
- **UNO Q(aarch64)에서도 같은 종단 검사 통과**: 정상 6회·비정상 4회의 격리된 합성 운전 사용. 최종 정상 후보 학습 약 0.34초, 분류 후보 약 0.71초. 다음 독립 합성 운전에서 정상 유사 → 비정상 유사·점검 권고 전환, 재시작 후 보고서 보존. `verification/auto-learning-unoq.json`.
- 정상 후보는 별도 정상 300창에서 오경보 0/300. 분류 후보는 별도 정상 300창·비정상 300창에서 오경보 0/300·검출 300/300. **설계된 합성 입력의 기능 검사이며 실제 발전기 정확도가 아닙니다.**
- 동일 평가 회차를 보존하고, 재학습만으로 기존 적용 모델이 바뀌지 않는 것을 검사.
- 실제 운영 DB에 합성 시험 라벨을 넣지 않음. 기존 실측 3회는 기존 검토 상태대로 보존.
- 수정 화면은 UNO Q에 적용했습니다. 역할 선택이 사라진 검토 창, 단일 AI 학습 버튼, 검토 자료 부족 안내를 실제 브라우저에서 확인했고 JavaScript 오류는 없었습니다.
- 갱신 후 실제 IMU 수신과 같은 정상 기준의 복원을 확인했습니다. 개인 부착 기준 파일과 고정 모델 파일 SHA-256은 갱신 전과 같습니다.

## 실행·범위

개발 실행은 [README](README.md), 기존 UNO Q 배치 재시작은 [보드 안내](deployment/UNO_Q_RUNBOOK.md)를 따릅니다. 이번 기능은 생성형 AI·고장 확률·고장 부위 확정·RUL 모델이 아닙니다. 실제 발전기와 추가 온도·압력 센서의 현장 검증은 수행하지 않았습니다.

GitHub 게시본에서는 실제 운영 DB, 개인 부착 기준 파일, 원시 센서 캡처·기기별 설정을 제외합니다. 런타임 필수 합성 seed DB인 `model_bundle/baseline.sqlite`만 예외로 포함합니다. 이 파일에는 실제 운전 데이터가 없습니다.

[이전 검증 이력](docs/PRE_AUTO_CURRENT_STATUS.md)은 당시 기록이며 현재 UI·사용 순서와 구분합니다.
