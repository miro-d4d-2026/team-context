# GenGuard 현재 상태 · 실측 ML 적용 · 2026-10-11

**정상·비정상으로 검토한 실측 진동 기록으로 UNO Q에서 두 모델을 학습·평가·적용했습니다. 현재는 보고서 기록 여부와 관계없이 새 IMU 창마다 보드가 판단하며, 전원 부팅 자동 시작 서비스도 설정했습니다. 사용자가 USB 전원을 분리·재연결한 뒤 자동 시작과 실측 수신 복구까지 확인했습니다.** 자세한 집계는 [실측 학습 결과](LIVE_LEARNING_RESULT.md), 사용 순서는 [자동 학습 안내](AUTO_LEARNING_GUIDE.md)를 따릅니다.

## 현재 사용할 수 있는 흐름

- 상단은 `모의 운전 / 실측 운전` 두 가지입니다. 과거 아이폰 실험 재생은 `분석 보고서 → 과거 진동 재생`에 있습니다.
- 운전 현황에서 실측 IMU 수신·새로 적용한 ML 모델의 연속 판단·기존 진동 기준과 진동 연동 모의 계측을 확인합니다.
- 기록에서 정상·비정상·판단 보류·측정 오류를 검토합니다. 사용자가 학습·보정·검증 역할을 지정하는 기능은 없습니다.
- 같은 장비·설치·출처의 승인 기록으로 `AI 학습`을 실행하면 시스템이 운전 회차별로 자료를 나누어 학습·평가합니다.
- 정상만 충분하면 정상 기준 모델을 만들고, 정상·비정상 사례가 충분하면 분류기도 학습합니다. 평가 분모와 자료 부족을 표시합니다.
- 성능 확인 후 `새 모델 적용`을 실행하면 다음 유효 센서 창부터 해당 조건의 모델을 사용합니다. 새 기록은 검토 후 누적하고, 필요할 때 같은 기능으로 재학습합니다. 기존 보고서는 보존합니다.
- `보고서 기록 시작 / 종료`는 운전 회차별 기록·보고서를 남기는 기능입니다. 시작 전이나 종료 후에도 두 학습 모델의 판단은 이어집니다. 보고서 버튼으로 경고 누적 횟수를 초기화하지 않습니다.
- 실제 장비·설치·센서 설정과 일치하는 활성 학습 조건이 하나일 때만 자동 연결합니다. 모델이 없거나 여러 조건이 겹치면 판단을 보류합니다. 입력 중단·무효 값·스트림 변경 시 연속 경고를 초기화하고 과거 판단을 현재 결과로 표시하지 않습니다.
- 웹 서버·학습·추론·저장은 UNO Q, Mac은 브라우저·USB 연결 담당입니다. `genguard.service` 및 사용자 로그인 유지(`Linger=yes`)로 부팅 자동 시작을 설정했습니다. 사용자가 전원을 분리·재연결한 뒤 서비스가 별도 실행 명령 없이 자동 기동하고 실측 수신이 복구됐습니다.

## 연속 판단·보고서 분리 확인

- 보고서를 기록하지 않은 상태에서 새 기준 진동 5창 모두 `reference / normal_like`로 판단했습니다. `fresh=true`, `recording=false`를 함께 확인했습니다.
- 실제 웹의 보고서 기록 시작·종료로 정상 5창의 새 보고서 `run-e3d7b20747cc`를 남겼고, 종료 후 다시 `recording=false`에서도 감시가 유지됨을 확인했습니다.
- 보드의 학습 모델 2개와 기존 계수는 변경하지 않았습니다. 위 보고서를 더해 현재 기록은 9개입니다. 이번 변경으로 재학습하지 않았습니다.
- 이번 배포에서도 기록 없이 강함 7창·간헐 7창 모두 점검 권고·비정상 유사를 확인했습니다.
- 실제 USB 전원 분리·재연결로 부팅 ID가 바뀐 것을 확인했습니다. 새 부팅에서 서비스는 자동으로 active/running, 재시도 0회였고, 기록 없이 fresh 실측 창과 두 모델 ID가 복구됐습니다. Mac에서는 화면 접속용 USB 터널만 다시 열었습니다. 모델 계수·기존 부착 기준·고정 모델 해시와 보고서 9개 보존을 확인했습니다.

이번 상시 분석 확인은 보고서 기록을 종료한 상태에서 **기준 진동 5/5창 정상 유사, 강한 진동 7/7창·간헐 진동 7/7창 점검 권고**였습니다. 간헐 7창은 기존 진동 패턴 분석에서도 간헐로 표시됐습니다. 이는 확인한 동일 부착 실측 창의 결과이며 일반 정확도 수치가 아닙니다. [확인 집계](verification/continuous-monitor-check.json)

## 코드 검증 이력

- 현재 연속 ML·보고서 분리 변경: 전체 Python **282개**, 웹 **163개**, 배포 자동 시작 전용 검사 **11개** 통과. 배포 검사는 앞의 전체 Python 결과와 별도로 실행했습니다. 수치 모델을 실제로 학습하는 격리 fixture로 기록 없는 정상·강함·간헐 판단, 보고서 시작·종료, 동일 창 저장, 재시작·중복·끊김·무효 입력·모델 조건 불일치를 검사했습니다.

- 후속 모드 명칭 정리: 상단 실측 운전과 과거 재생 분리, JavaScript **161개 통과**. UNO Q 적용 후 과거 재생 진입·구간 이동·실측 복귀 확인. 기존 학습 모델 2개·운전 기록 8개 보존 및 센서 수신 복구 확인.
- 이번 정리: 사용되지 않는 화면 코드 정리, 로컬 코드 커밋 `45a6383`. 관련 JavaScript **160개 통과**.
- 앞선 화면 코드 정리 시점에는 백엔드를 변경하지 않았으며 Python **270개 통과**는 당시 이력입니다. 현재 백엔드는 연속 ML 추론을 추가했고 위 282개 결과를 따릅니다.
- 앞선 화면의 JavaScript **164개·160개·161개 통과**는 해당 단계의 이력입니다. 현재 화면 검증은 위 163개 결과를 따릅니다.
- 앞선 격리된 합성 데이터 시험에서는 초기 학습·누적 재학습·명시적 적용·새 운전·재시작 후 보고서 보존을 Mac과 UNO Q에서 확인했습니다. 이번 실측 확인과 합성 검증을 구분합니다.
- 이번 실측 확인은 실제 UNO Q에서 수행한 학습·평가·모델 적용과 새 운전 판단입니다. 이전의 실측 3회 미검토 상태는 위 검토·추가 수집으로 갱신되었습니다.

## 실행과 게시 범위

개발 실행은 [README](README.md), 기존 UNO Q 배치 재시작은 [보드 안내](deployment/UNO_Q_RUNBOOK.md)를 따릅니다. 이 기능은 생성형 AI·고장 확률·고장 부위 확정·RUL 모델이 아닙니다. 실제 발전기와 추가 온도·압력 센서의 현장 검증은 수행하지 않았습니다.

GitHub 게시본은 공개 가능한 코드와 집계 결과만 포함합니다. 실제 운영 DB, 개인 모델 계수·부착 기준, 원시 센서 캡처와 기기별 설정은 제외합니다. 로컬 검증 원본도 이 게시본에 포함되지 않을 수 있습니다. 런타임 필수 합성 seed DB인 `model_bundle/baseline.sqlite`만 예외로 포함하며, 여기에는 실제 운전 데이터가 없습니다. 공개 코드만 실행하면 개인 실측 모델과 운영 기록은 자동 복원되지 않습니다.

[이전 검증 이력](docs/PRE_AUTO_CURRENT_STATUS.md)은 당시 상태이며 현재 UI·모델 적용 상태와 구분합니다.
