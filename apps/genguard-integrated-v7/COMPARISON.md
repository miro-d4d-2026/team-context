# GenGuard v7 — 팀 구현 비교와 채택 근거

작성: 2026-10-11. 사용자의 요청에 따라 받은 팀 저장소·ZIP과 기존 로컬 v6를 비교했다. 아래 성능은 해당 데이터·컴퓨터에서 확인한 범위이며 실제 발전기 성능으로 확장하지 않는다.

## 비교한 원본

- 팀 저장소: https://github.com/miro-d4d-2026/team-context
- 받은 커밋: `91d0f578cf5288ba6449ce8daa7c50d8d91fe752` (`main`). 현재 이후의 원격 변경까지 확인했다는 뜻은 아니다.
- 미로 관제: `apps/genguard-console/README.md`, `server.py`, `static/index.html`
- 공통 엣지 모델: `apps/genguard-edge-v1/README.md`, `genguard/model.py`
- 이치 제공 ZIP: `GenGuard-Predictive-AI.zip`, 압축 해제한 40개 파일
- 팀 저장소 `apps/genguard-predictive`의 40개 파일과 ZIP의 40개 파일은 **경로별 SHA-256이 전부 같다**. 두 개의 독립 구현으로 중복 평가하지 않았다.
- 기존 로컬 구현: `genguard-operation-v6`의 운전 구간 모델·기록·진동 재생 모델

읽은 README의 과거 합의보다 사용자의 최신 요청을 적용했다. 발전기 프로필은 기존에 고정한 **10 kW·208 V 선간전압·60 Hz·1,800 rpm**을 유지한다. 공통 CONTEXT의 과거 240 V 시연값을 섞지 않는다.

## 채택한 진동 모델 개선

`vibration_classifier.py`는 기존 두 숫자 입력 API를 유지한다.

```python
result = classifier.classify(rms_g, envelope_cv)
```

- 이치의 `phone-pattern-repeat12-cal3-v1` 모델을 `replay_artifacts/phone-pattern-calibrated-v1.json`에 바이트 그대로 보존했다.
- 반복 수집의 1·2회 **32개 창으로 학습**, 3회 **16개 창으로 거리 기준 보정**을 한다.
- 2초 창의 벡터 RMS와 100 ms 구간별 진동 세기의 변동계수를 사용한다. 각 축의 평균을 제거한다.
- 새 진동이 네 가지 학습 패턴에서 너무 멀면 `label=unknown`, `state=unavailable`을 반환한다. 임의로 정상이나 강한 진동이라고 고르지 않는다.
- 거리 기준은 학습·보정 창의 최대 참 클래스 거리 × 1.25다. 작은 표본을 대상으로 한 개발 가드이며 통계적으로 보장된 미지 고장 검출률은 아니다.
- 결과에 `model_distance`, `acceptance_radius`, `unknown_reason`을 포함한다. `confidence`는 여전히 null이며 확률처럼 표시하지 않는다.
- 학습한 패턴은 아이폰의 명령된 진동 종류다. 발전기 고장 종류가 아니다. `generator_fault_diagnosis=false`를 반환한다.
- 기존 v5/v6 모델·원시 특징·평가 파일과 해시 manifest는 덮어쓰지 않았다. 현재 API가 제공하는 평가와 모델 ID는 새로운 모델을 따라 다시 계산한다.
- 원본 모델의 SHA-256과 가져온 경로는 `replay_artifacts/phone-pattern-calibrated-provenance.json`에 기록했다. 팀이 전달한 자료를 요청 범위에서 통합했으며 별도 외부 재배포 라이선스를 추정하지 않는다.

### 검증 결과

우리 v6와 이치 ZIP에 든 반복 48개·무작위 48개 창의 RMS/CV를 대조했으며 각 값이 정확히 같았다. 해당 실측 특징을 새 모델에 다시 넣은 결과:

| 별도 무작위 기록 1개, 48개 2초 창 | 맞춘 창 / 전체 | 판단 보류 |
|---|---:|---:|
| RMS만 사용한 비교 모델 | 36 / 48 | 0 |
| RMS+시간 패턴 모델, 거리 보류 적용 | 48 / 48 | 0 |

분모 48은 서로 관련된 한 녹화의 구간 수이며 독립된 장비 48대/시험 48회가 아니다. 전체 163초 중 자극 구간 96초만 평가했다. 전이·대기 구간과 새로운 부착 위치·받침·센서에 대한 성능은 검증하지 않았다. 합성으로 매우 큰 CV를 넣어 **학습 범위 밖 입력이 정상/장애로 강제 분류되지 않고 보류되는 기능**도 확인했다. 이것을 실제 미지 고장 검출 성능으로 해석하지 않는다.

관련 검증 명령:

```sh
python3 -m unittest test_vibration_classifier -v
```

11개 테스트에서 학습 계수·거리 기준 재현, 테스트 라벨/시간 순서 비의존, 모델 불변성, 원본 해시, 48개 별도 기록 평가, 미지 입력 보류를 확인했다.

## 실제 연결에서는 부착 기준을 우선

아이폰을 다른 곳에 붙이면 진동 전달 크기가 바뀔 수 있다. 따라서 실시간 주 판단은 **지금 부착한 상태에서 정상 진동을 등록 → 이후 크기·패턴 변화 확인**으로 유지한다. 과거 아이폰 4종 모델의 재생 결과와 실제 연결 분석은 출처를 분리한다.

이치 코드에는 2초 창·순번 연속성·최대 간격 10 ms·180–240 Hz·포화 확인·부착 프로필 확인이 있다. 이중 180–240 Hz는 원본 약 209 Hz 기록을 위한 가드이며 현재 UNO Q 수집률을 확인하지 않고 모든 입력에 강제 적용하면 실측을 계속 거부할 수 있다. 실측 수집부에서는 실제 샘플률/누락/기준 등록 상태를 표시하고 그 계약에 맞게 검증해야 한다. 벡터 RMS와 축 평균 RMS는 √3 차이가 있으므로 혼용하지 않는다.

## 미래 예측은 왜 주 모델로 교체하지 않았나

이치 계측 모델은 **78입력 → 96 → 64 → 44출력 MLP**로, 11개 계측의 30/60/120/180초 후 변화량을 예측한다. 학습 데이터는 전부 합성이다. 고정 2초 간격, 연속 180초 이력, `running` 단계, 부하 20–92%, 외기온 11–37°C가 적용 범위다. 별도 합성 운전으로 예측 오차 구간을 보정했다.

현재 v6는 시동 후 0·5·10·15·20분의 3종 계측을 비교한다. 이 표를 2초 데이터처럼 채우거나 11개 센서의 빠진 값을 임의로 넣어 MLP를 연결하면 실제 관측이 없는 이력을 만든다. 예열 중 수온 상승률을 보려는 사용자의 요청과도 맞지 않는다.

그래서 v7의 주 분석은 **동일 운전 구간의 이전 점검 대비 변화**로 유지한다. 예측 모델은 필요한 실제 연속 계측과 적용 조건을 갖춘 뒤 보조 패널로 연결할 후보로 남긴다. 학습된 예측이라는 이유만으로 현재 구간 분석보다 더 정확하거나 유용하다고 판단하지 않았다.
