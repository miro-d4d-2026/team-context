# 실측 진동 학습·재생 모델 · v7

반복 테스트에서 **기준·강한·간헐·무진동의 특징을 학습**했고, 같은 부착 조건의 별도 랜덤 테스트에 재학습 없이 적용했습니다. 실제로 학습한 것은 네 가지 패턴의 중심과 데이터의 평균·표준편차입니다. 앱의 정답 순서를 읽어 답을 정하는 방식이 아닙니다.

## 결과와 해석

| 모델 | 별도 랜덤 기록의 2초 구간 | 10초 자극별 다수결 |
| --- | --- | --- |
| 진동 세기(RMS)만 학습 | 36 / 48 | 9 / 12 |
| 진동 세기 + 시간 패턴(CV) 학습 | 48 / 48 | 12 / 12 |

랜덤 기록에서 기준 진동의 세기가 학습 때보다 낮아졌습니다. 세기만 비교한 모델은 이를 간헐 진동으로 오인했고, 진동이 일정하게 이어지는지 함께 본 모델은 구분했습니다.

이 결과는 **아이폰 실험 녹화 한 건의 48개 평가 창**에 대한 결과입니다. 48번의 독립 실험이나 발전기 고장 진단 정확도를 뜻하지 않습니다. 센서 위치·방향·받침은 이전 실험과 동일했다고 사용자가 확인한 조건입니다. 새로운 부착 환경과 실제 발전기에는 새 검증이 필요합니다.

## 화면 상태로 바꾸는 정책

| 학습된 패턴 | 화면 상태 | 의미 |
| --- | --- | --- |
| 기준 진동 | 정상 | 이 실험의 기준 진동과 유사 |
| 강한 진동 | 점검 | 기준보다 강한 진동이므로 부착·부하·운전 상태 확인 |
| 간헐 진동 | 점검 | 일정하지 않은 반복 진동이므로 운전 상태 확인 |
| 무진동 | 진동 미감지 | 정지 구간인지 확인; 고장으로 단정하지 않음 |

`정상`은 이 실험의 진동 패턴에 대한 상태입니다. 발전기 전체가 정상이라는 판정은 아닙니다. 고장 원인이나 부품 수명을 학습한 모델도 아닙니다. 온도·유압의 기존 모델과는 서로 다른 모델이며, 측정 대상과 학습 출처를 구분해 보여줍니다.

## 입력과 학습 방법

- 원시 가속도 3축을 2초씩 자르고 각 축의 평균(중력·DC)을 제거합니다.
- RMS는 중심화된 3축 가속도의 합성 세기입니다.
- CV는 100ms 단위 진동 세기의 표준편차/평균으로, 일정함과 간헐성을 구분합니다. 각 100ms 구간도 별도로 축 평균을 제거하며, 최소 5개 샘플을 요구합니다.
- `log(RMS)`와 CV를 **반복 기록만으로** 표준화하고 클래스별 중심을 학습합니다.
- 실행 시 현재 특징과 가장 가까운 클래스 중심을 구하고, 보정된 수용 거리 안일 때만 해당 종류로 표시합니다. 정답·시간·주기·순서는 모델 입력이 아닙니다.
- v7은 학습 범위 밖 진동을 `unknown / 판단 보류`로 표시합니다. 이 거리는 고장 확률이 아니며 새 환경의 미지 고장 검출 성능을 보장하지 않습니다.

훈련: `399032D5-A905-4B15-B7C5-F5367DEFAFAA` / 반복 녹화1건에서1·2회32창 학습, 3회16창 수용 거리 보정. 이치의 검증된 모델을 원본 그대로 가져왔습니다.

별도 검증: `4EBCA240-73C0-4FEC-999C-136073E774E8` / 무작위 녹화 1건 / 48개 창.

첫 반복 기록의 간헐 진동 구간에는 원인을 모르는 큰 충격이 있습니다. 이를 제외하지 않고 원래 데이터 그대로 학습·검증했습니다.

## 재생 시간의 의미

각 10초 자극에서 시작 0.5초 후부터 2초 창 네 개, 즉 8초를 평가합니다. 총 12개 자극, 96초의 평가 창입니다. 실험 전체는 163초이고, 대기·전이·나머지 구간은 미평가입니다. 따라서 웹에서는 **평가 구간을 순서대로 재생**하며 원래 기록 시간을 함께 표시합니다. 연속 실시간 분류를 입증하는 시연으로 설명하지 않습니다.

원래 시간은 `recorded_at + start_s/end_s`로 표시할 수 있습니다. 이 시간은 센서·PC·아이폰의 동기 신호로 맞춘 기록 시각이며, 정밀한 물리 지연 보정값은 아닙니다. 오늘 분석하는 시각과 분리해야 합니다.

## 파일과 실행

- `vibration_classifier.py`: Python 표준 라이브러리만 사용하는 런타임. 인터넷·외부 API 필요 없음.
- `replay_artifacts/phone-pattern-calibrated-v1.json`: 현재 사용 중인32학습+16보정 모델. 출처·해시는 같은 폴더 provenance JSON에 있습니다. `model.json`은 이전 v6모델 원본을 보존한 파일입니다.
- `replay_artifacts/training.json`, `random.json`: 원시 측정에서 다시 계산한 2초 특징값. `expected_label`은 평가 화면용 정답이며 추론에 사용하면 안 됩니다.
- `replay_artifacts/catalog.json`: UI 목록과 검증 요약.
- `replay_artifacts/frozen-original.json`: 원래 학습 직후 동결한 모델의 바이트 원본. 내부의 “아직 별도 평가 없음” 문구는 당시 상태를 보존한 것이며 현재 결과는 `random.json`에 있습니다.
- `replay_artifacts/manifest.json`: 재생 산출물 해시와 원시 재계산 확인.
- `build_vibration_replay.py`: 원시 CSV·아이폰 로그를 읽어 모든 산출물을 재생성. ZIP 내부 코드는 실행하지 않습니다.

```python
from vibration_classifier import classify, load_recording

frame = load_recording("random")["frames"][0]
result = classify(frame["rms_g"], frame["envelope_cv"])
print(result["title"], result["summary"])
```

원시 데이터가 있는 개발 환경에서 재생성할 때만 NumPy와 pandas가 필요합니다.

```sh
python3 -m pip install numpy pandas
python3 build_vibration_replay.py --source-root ../iphone-imu
python3 -m unittest test_vibration_classifier -v
```

원본 ZIP 두 개와 보존된 `iphone-imu/20261010T101556/inputs`, `20261010T104429/inputs`, 첫 기록의 `frozen-classifiers.json`, `analysis-source.py`가 필요합니다. ZIP·원시 파일·과거 모델·추출기 해시가 다르면 재생성을 중지합니다. 추출기는 바이트만 검증하고 코드를 불러오지 않습니다.

재계산한 모델 파라미터와 동결 모델의 최대 차이는 약 `2.22e-16`이었습니다. 이 재계산 수치는 보존한 v6모델의 재현 결과입니다. v7활성모델의32/16분리·거리 보정 재현은 `test_vibration_classifier.py`와 `COMPARISON.md`를 참고하세요. 무작위 기록은 학습·기준 조정에 넣지 않았습니다.

UNO Q로 폴더를 옮기면 동일한 Python 추론을 실행할 수 있는 구조입니다. 실제 UNO Q센서에서USB로데이터를받아Mac에서특징계산·분석하는연결을완료했습니다. 이4종분류기는기록재생용이며 실시간주판정은새부착기준을별도로학습합니다. UNO Q에서분석까지실행한것은아닙니다.
