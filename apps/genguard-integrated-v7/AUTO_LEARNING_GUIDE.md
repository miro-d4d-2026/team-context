# GenGuard 자동 학습 사용 안내

2026-10-11. 정비사는 **데이터의 상태**를 확인하고, 시스템은 그 데이터를 **학습·경계 조정·평가에 어떻게 사용할지** 결정합니다.

## 사용자가 할 일

1. 보고서로 남길 운전에서 `보고서 기록 시작 → 보고서 기록 종료`를 누릅니다. 센서 수신과 적용 모델의 상시 판단은 기록 여부와 무관하게 계속됩니다.
2. `기록 · 정상 검토`에서 **정상 확인 / 비정상 확인 / 판단 보류 / 측정 오류**를 선택하고, 검토자와 확인 근거를 저장합니다. 필요한 경우 구간별 상태를 지정합니다.
3. `학습 센터`에서 같은 장비·설치 조건의 기록 묶음을 선택하고 **AI 학습**을 누릅니다. 사람이 학습·보정·검증 역할을 지정하지 않습니다.
4. 정상/비정상 기록 수, 오경보율, 비정상 검출률, 기존 적용 모델과의 비교를 확인합니다.
5. 통과한 후보의 **새 모델 적용**을 누릅니다. 같은 설치·센서 조건의 다음 유효 실측 창부터 해당 모델이 적용됩니다. 기존 운전의 판단·보고서는 바뀌지 않습니다.

새로 승인한 기록을 포함해 같은 버튼을 다시 누르는 것이 재학습입니다. 기록이 추가될 때마다 자동으로 모델을 교체하지 않습니다.

## 시스템 내부 처리

- 같은 장비·부착 위치·입력 종류·운전 조건·센서 설정끼리 묶습니다. 실측 진동과 모의 발전기 데이터는 서로 다른 학습 대상입니다.
- 미검토·판단 보류·측정 오류 기록은 학습하지 않습니다. 운전 중인 기록도 사용하지 않습니다.
- 정상만 모이면 정상 패턴 모델을 학습합니다. 정상·비정상 사례가 충분하면 별도의 분류기도 함께 학습합니다.
- 독립 운전 회차를 통째로 분리합니다. 한 운전의 앞부분을 학습하고 뒷부분을 독립 평가라고 표시하지 않습니다.
- 기존 평가 회차는 재학습에서도 학습 자료로 돌리지 않습니다. 과거에 학습·경계 조정에 사용한 회차를 새 평가 자료로 바꾸지도 않습니다.
- 분리 결과는 각 후보 모델에 보존합니다. 사람의 상태 판정과 기존 기록의 역할 필드를 시스템이 덮어쓰지 않습니다.
- 평가 기록을 반복 사용했다면 재사용이라고 표시합니다. 이 결과를 새로운 독립 최종 시험 성능이라고 주장하지 않습니다.

## 데이터가 부족하면

초기 정상 모델에는 **유효한 독립 정상 운전 4회 이상**이 필요합니다. 각 회차의 안정 운전 분석 창은 30개 이상이고 유효율은 95% 이상이어야 합니다. 내부적으로 최소 2회 학습, 1회 경계 조정, 1회 평가에 사용합니다.

분류기는 정상과 비정상 각각 같은 조건이 필요합니다. 정상·비정상 구간을 함께 가진 독립 운전 4회도 각 구간의 유효 창 수 조건을 충족하면 사용할 수 있습니다. 이 수량은 프로토타입 정책이며 발전기 현장 성능을 보장하는 수량은 아닙니다.

한 번에 최대 30회 기록을 처리합니다. 더 많은 기록은 계속 보존되며, 학습 센터에서 사용할 기록 범위를 조정할 수 있습니다. 역할을 수동 지정하는 기능은 없습니다.

## 성능 수치의 의미

- **정상 오경보율:** 분리한 평가 자료 중 정상 창을 이상으로 판단한 비율.
- **비정상 검출률:** 분리한 평가 자료 중 비정상 창을 검출한 비율. 정상 전용 평가에는 비정상 검출률을 만들지 않고 미평가로 표시합니다.
- **기존 모델 비교:** 같은 조건의 기존 적용 모델과 같은 평가 자료에서 비교합니다. 비교 불가 또는 성능 간 득실이 있으면 그대로 표시합니다.
- **적용 가능 후보:** 개발 정책의 기준을 통과한 후보라는 의미입니다. 발전기 고장 확정·고장 확률·RUL 보증이 아닙니다.

합성 기록으로 실제 ML 학습 동작을 검증할 수 있지만, 그 성능은 실제 발전기의 성능과 다릅니다. 실제 발전기가 없는 이번 시연에서는 진동만 실측이며 나머지 계기값은 모의입니다.

## 연결 API

```json
POST /ui-api/review
{"session_id":"run-...","status":"normal","reviewer":"담당자","note":"점검 근거"}

POST /ui-api/training-plan
{"session_ids":["run-..."]}

POST /ui-api/train
{"kind":"auto","session_ids":["run-..."]}

POST /ui-api/activate
{"kind":"normal","model_id":"review-..."}
```

UI가 자동 준비 결과를 받아 학습 가능 여부를 표시합니다. API의 기존 수동 분할 경로는 과거 코드와의 호환용으로 남아 있으며 사용자 화면에는 노출하지 않습니다.

새 모델은 `context-ridge-residual-covariance/1` 코어를 재사용한 정상 기준과, 별도의 `genguard-reviewed-quadratic-logistic/1` 분류기입니다. UNO Q의 NumPy로 학습·판단합니다. 새 분류기가 CLIKA로 실행된다고 주장하지 않습니다.

## 재현 검사

앱 폴더에서 실행합니다. 아래 검사는 임시 데이터베이스를 사용하며 실측 기록에 라벨을 붙이거나 실제 운영 모델을 바꾸지 않습니다.

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s . -p 'test_*.py' -q
node --test web/test_*.mjs
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 deployment/verify_auto_learning.py --output /tmp/genguard-auto-proof.json
```

최신 검증 결과와 게시 범위는 `CURRENT_STATUS.md` 및 `verification/auto-learning-*.json`을 참고합니다. 기존 역할 지정 방식의 문서는 과거 이력입니다.

## 같은 조건으로 다음 실측 운전 시작

`센서 · 입력 연결`에서 기록 이름과 **운전 조건**을 확인합니다. 적용된 실측 진동 모델이 있으면 그 모델의 조건을 제안합니다. 실제 부착 위치·받침·구동 조건이 같은 경우에만 같은 조건명을 사용합니다. 직접 수정한 값은 화면 새로고침 주기에서 덮어쓰지 않습니다.

구간별로 정상·비정상을 함께 검토한 회차는 `구간 검토`로 별도 집계합니다. 전체 정상·전체 비정상 회차 수에 중복 합산하지 않습니다. 학습 결과에서는 실제로 사용된 라벨별 회차 수와 평가 창 수를 확인할 수 있습니다.
