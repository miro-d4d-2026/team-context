# 점검 이력 비교 모델

`model.json`은 정상으로 승인한 **합성 점검 8회·240개 진동 특징 창**으로 실제 학습한 Ridge 회귀 계수와 잔차 크기입니다. `seed-history.json`은 그 학습 기록, `evaluation.json`은 별도 운전 120회의 평가 결과입니다. 실제 발전기의 정상 범위나 고장 정확도를 나타내지 않습니다.

## 무엇을 학습하는가

부하율·외기온·RPM·시동 후 경과 시간과 수온·유압·진동 사이의 정상 관계를 학습합니다. 진동은 로그 변환합니다. 수온·유압·진동을 각각 따로 학습하므로 실측 진동과 모의 발전기 값을 서로 물리적으로 연관된 센서로 학습하지 않습니다.

실측 진동에 모의 부하·외기온을 넣어 정상 관계를 학습하는 것도 금지합니다. 실측·재생 IMU의 조건 보정은 운전 조건의 출처가 실제 컨트롤러·센서·기기 시계일 때만 가능합니다. 지금 가진 IMU와 웹 모의값 혼합 시연에서는 **발전기 모의 조건 비교 + 별도의 실측 진동 정상 기준 비교**를 사용합니다.

`InspectionComparator(records).compare(current, reference_id=None)`는 현재 시점 이전의 같은 장비 기록 중, 정상 승인을 받은 자료만 학습합니다. 현재 값이나 미승인·이상 기록은 자동 학습하지 않습니다. 운전 종료 후 정상 승인 기록을 저장하고 Comparator를 다시 만들면 새 기록을 반영할 수 있습니다. `export_model(current)`으로 해당 기준의 학습 계수를 JSON 저장합니다. 외부 서버·LLM은 필요 없습니다.

## 어떤 이전 점검과 비교하는가

- 같은 장비, `running` 단계, 시동 후 최소 300초
- 부하 차이 5%p 이내, 외기온 5°C 이내, RPM 50 이내, 경과 시간 120초 이내
- 위 조건에 맞는 가장 최근의 **승인 정상 점검**. 직전 이상 기록을 정상 기준으로 사용하지 않습니다.
- 진동은 출처·부착 식별자·설정 샘플링 속도·창 길이·DC 제거·특징 버전이 같아야 합니다. 가속도 범위나 추가 설정 ODR이 있으면 이것도 같아야 합니다.
- 해당 출처의 정상 운전 최소 3회·중복 제거한 창 36개가 필요합니다. 단일 스냅샷을 여러 창으로 부풀리지 않습니다.

화면에 표시할 원시 차이와 운전 조건 보정 차이를 함께 반환합니다. 이전 값을 현재 부하·외기온 등에 해당하는 값으로 이동시킨 후 비교합니다. 누락·오래된 값·조건 불일치는 해당 채널을 `unavailable`로 반환하며 정상으로 간주하지 않습니다.

## 점검 권고 기준

학습 정상 기대값에서 벗어난 크기 또는 조건 보정 후 이전 정상 점검과의 차이가 설정 범위를 넘으면 점검 권고를 반환합니다. 범위는 정상 기록의 잔차 3배(두 점검 차이는 √2 보정)와 다음 개발 설정 중 큰 값입니다.

| 항목 | 최소 개발 설정 |
|---|---:|
| 수온 | 2°C |
| 유압 | 0.2 kgf/cm² |
| 진동 | 로그 비율 ln(1.25) |

이것은 제조사 경고·정지 한계값이 아닙니다. 보호 경보는 기존 별도 규칙을 사용합니다. 원인 후보·점검 항목은 고정된 설명 규칙이며, 학습 모델이 고장 부위를 확정하거나 문장을 생성하는 것이 아닙니다. 미래 고장 시점과 RUL도 예측하지 않습니다.

## 검증 결과와 한계

정책을 고정한 뒤 훈련 seed 1100–1107과 겹치지 않는 120개 전체 운전을 평가했습니다. 행을 무작위로 나눠 같은 운전이 학습·평가 양쪽에 들어가는 방식을 쓰지 않았습니다.

| 합성 시나리오 | 20회 결과 |
|---|---|
| 정상 유지 | 20회 정상 |
| 조건 변화에 맞춘 정상 수치 이동 | 20회 정상 |
| 수온 +7°C | 20회 수온 점검 |
| 유압 −0.65 kgf/cm² | 20회 유압 점검 |
| 진동 ×1.65 | 20회 진동 점검 |
| 위 세 변화 동시 발생 | 20회 세 항목 점검 |

**같은 합성식 계열에서 생성한 큰 변화 시나리오의 기능 검증입니다.** 실제 장비 일반화·고장 정확도·작은 변화의 검출 한계는 검증하지 않았습니다. 평가 현재 값은 30개 창의 평균이고, 실시간 1개 창과 이전 평균 비교에서 생길 잡음 영향도 별도 현장 확인이 필요합니다. 단위 테스트는 현재·미래 기록 유입, 미승인 이력, 정상 회복, 누락·오래된 값, 출처·부착·샘플링 변경을 검증합니다.

## 재현

```sh
python3 train_inspection.py
python3 -m unittest test_inspection_model -v
```

필요 라이브러리는 기존 패키지의 NumPy 하나입니다. 학습과 추론은 CPU에서 수행합니다. UNO Q 실기 실행 시간과 메모리는 이 결과로 측정한 것이 아닙니다.
