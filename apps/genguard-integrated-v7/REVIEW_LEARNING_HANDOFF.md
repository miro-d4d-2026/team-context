# GenGuard 검토·학습 통합 사용 안내

2026-10-11. **기존 IMU 수신·진동 정상 기준을 유지하면서, 사람이 검토한 정상·비정상 기록으로 후보를 학습하고 다음 운전에 적용하는 흐름을 추가했습니다.** 현재 접속 주소는 [http://127.0.0.1:9883/](http://127.0.0.1:9883/)입니다.

## 지금 유지되는 것과 새로 추가한 것

| 영역 | 동작 |
|---|---|
| 기존 실시간 감시 | UNO Q의 IMU 수집·RMS/CV 계산·기존 정상 기준 비교·모의 RPM/전압 연동 유지 |
| 기록·사람 검토 | 미검토 / 정상 / 비정상 / 판단 보류 / 측정 오류·제외, 구간 라벨, 작성자·근거·변경 이력 |
| 정상 기준 학습 | 승인한 정상 기록만 사용. 기존 `context-ridge-residual-covariance/1`의 수치 계산 재사용 |
| 라벨 분류 학습 | 별도 `genguard-reviewed-quadratic-logistic/1`이 정상·비정상 숫자 특징을 학습 |
| 적용·보고서 | 검증 후 별도 활성화, 다음 운전 시작 때 모델 고정, 당시 판단·사람 검토·조치 이력 분리 |

새 학습 모델은 **NumPy로 실행**합니다. 생성형 LLM이나 고장 부위·확률·RUL 모델이 아닙니다. 기존 팀 Clika 실행 경로는 변경하지 않았으며, 새 라벨 분류기를 Clika로 실행했다고 주장하지 않습니다.

기존 기준은 `imu-a9bad4ae32431366e759`, 고정 발전기 모델은 `gg-61d42414c27fc19fa7a5`입니다. 이번 보드 확인 당시 서버 PID는 **1463**이었고, PID는 재시작하면 바뀝니다. 기존 데이터·모델·특징 계산 등 37개 파일의 SHA-256이 변경 전과 일치했습니다.

## 실제 IMU로 사용할 순서

1. **센서·입력 연결 → 실측 IMU를 운전 기록으로 남기기**에서 이름을 입력하고 `운전 기록 시작`을 누릅니다. 시작 후 들어온 새 2초 특징 창을 저장합니다. 기존 실시간 감시는 계속됩니다.
2. 기록을 마치면 `기록 종료 · 검토하기`를 누릅니다. 기록 전체 상태 또는 필요한 시간 구간에 라벨을 지정하고 **검토자·확인 근거**를 적습니다.
3. 각 기록에 `학습 / 보정 / 검증` 역할을 정하고 `검토 · 역할 저장`을 누릅니다. 같은 운전의 구간들을 서로 다른 역할로 나눌 수 없습니다. 부분 라벨의 나머지 구간은 미라벨이며 경계에 걸친 창은 제외됩니다.
4. **기록·정상 검토**에서 사용할 기록을 선택하고 **학습 센터**로 이동합니다. `정상 기준` 또는 `검토 라벨`을 선택한 뒤 `선택 기록으로 후보 학습`을 누릅니다.
5. 검증 결과를 확인하고, 통과 후보에서 `다음 운전에 적용`을 누릅니다. 다음 기록을 시작하면 해당 모델 ID가 고정됩니다. 가동 중에는 모델을 교체하지 않습니다.
6. **분석 보고서**에서 당시 모델 판단과 현재 사람 검토를 함께 보고 담당자 조치를 기록합니다. 라벨을 바꾸거나 메모를 써도 과거 판단은 바뀌지 않습니다.

정상 기준은 **정상 독립 운전 2회 학습 + 1회 보정 + 1회 검증**, 회차당 유효 창 30개 이상이 필요합니다. 라벨 분류기는 **각 클래스가** 학습에 독립 운전 2개 이상, 보정·검증에 각각 1개 이상 있어야 하며 각 단계·클래스의 유효 창도 30개 이상 필요합니다. 정상·비정상 구간이 함께 있는 독립 운전 4개를 2/1/1로 나누는 방식도 가능합니다. 이는 개발 정책이며 실제 발전기에 충분한 데이터라는 보증이 아닙니다.

라벨이 부족하면 기록은 저장하고 새 분류기 학습만 대기합니다. 기존 진동 정상 기준은 계속 사용할 수 있습니다. 새 분류기가 정상이라고 해도 기존 진동 변화나 보호 참고 경고를 없애지 않습니다.

## 기존 아이폰 기록과 이번 실측 확인

- 반복·무작위 녹화 **2개, 각각 48창**을 원본 특징과 출처를 보존하여 가져왔습니다. 상태는 모두 `미검토`, 역할은 `미지정`입니다.
- 아이폰 버튼 이름을 사람의 정상·비정상 승인으로 자동 변환하지 않습니다. 동일 파일을 다시 가져와도 독립 기록 수를 늘리지 않습니다.
- 두 녹화만으로 새 분류기의 2/1/1 독립 운전 조건을 충족할 수 없습니다. 48창을 48회 운전으로 취급하지 않습니다.
- 이번 통합 뒤 실제 UNO Q에서 **새 IMU 4창**이 검토용 기록으로 저장되고 원본 수신 특징 패킷을 내보낼 수 있는 것을 확인했습니다. 이 4창은 미검토이며 새 정상·비정상 분류기의 실제 성능 평가나 재학습 결과가 아닙니다.
- `기록 · 판단 JSON`은 결과·검토 내용을, `수신 원본 다운로드`는 보존된 특징 JSON/JSONL을 내보냅니다. 새 수신 JSONL은 2초 특징 패킷이며 원시 가속도 CSV라고 부르지 않습니다. 과거 원시 CSV는 기존 `iphone-imu` 자료에 그대로 있습니다.

## 준비된 합성 시연으로 학습 흐름 확인

**학습 센터 → 별도 합성 학습 실험**을 펼칩니다.

1. `정상 모의 기록 만들기` → 생성된 4개를 검토하고 정상, 역할 2/1/1로 저장합니다.
2. 그 4개를 선택해 정상 기준 후보 학습 → 검증 결과 확인 → 별도 적용합니다.
3. `비정상 모의 기록 만들기` → 추가 4개를 비정상, 역할 2/1/1로 검토합니다.
4. 정상·비정상 8개를 선택하고 `검토 라벨 · 정상 / 비정상 분류`로 후보 학습 → 검증 → 적용합니다.
5. `새 모의 운전 시작`을 누르고 평소 운전, 진동 증가, 간헐 진동, 유압 변화, 복합 변화, 입력 누락을 바꿔 봅니다. **별도 합성 학습 실험 카드**에 그 실험의 값·모델 예상·판단이 함께 표시되고 선택한 증상에 맞는 그래프로 전환됩니다.
6. 종료 후 보고서에 조치를 쓰고 다시 조회합니다.

합성 시연은 기존 10kW/208V 참고 설정을 사용합니다. 대시보드의 실제 IMU와 모의 발전기 계기값을 실제 발전기의 동시 측정값으로 섞어 학습하지 않습니다. 이 합성 모델을 실제 IMU 모델로 이름만 바꿔 적용할 수도 없습니다.
