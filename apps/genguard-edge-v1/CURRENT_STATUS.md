# 현재 상태 / 다음 담당자 인계

2026-10-10. 제품: 구형·신형 발전기의 기존 컨트롤러 값과 추가 IMU를 동일 UI로 분석하는 온디바이스 정비 지원.

## 완료

- NumPy 기반 조건 보정 회귀 + 다변량 잔차 모델. JSON 저장, SQLite 운전 이력.
- 운전 후 정상 검토 → 학습/보정/검증 세션 분리 → 다음 운전 적용. 초기 기준 보존.
- 기존 UNO Q gateway(보드 localhost:9877) 구독 어댑터, snapshot 입력, read-only 결과 API9878.
- 실측/모의/공개재생/혼합시연 경계. 혼합시연에서도 각 채널 출처 보존.
- 단위·결측·오래된 값·설치·재시작·동시 학습·정상 검토 철회 등 53개 테스트 통과.
- Mac localhost HTTP 결과 API, pagination/CORS/입력 오류 확인 완료.
- 합성 시험: 온도/압력 변화 시작 240초, 통합 모델 지속 경보262초(22초 후). 진동-only 대상 모델은 지속 경보 없음. 진동 변화는244초(4초 후) 경보. 이는 모의 결과.
- 실제 공개 엔진 원본16CSV/114,770행/CC BY4.0 확보. 원본파일 겹치지 않는 평가. 현재5채널 모델은 고장 시험3개 모두 미탐지. 해당 후보 비활성 유지.

## 남은 인수

1. 미로가 보드에 패키지/NumPy 설치, 실제 gateway 패킷과 모델 어댑터 연결 확인.
2. 같은 설치에서 실제 IMU + 명시 모의 컨트롤러로 여러 독립 운전을 기록하고 보드에서 학습/다음 운전 비교.
3. 인터넷 없이 새로운 입력의 판단·로컬 기록이 계속 생성되는지 확인. 기록 시각/모델버전/보드 프로세스 증거 확보.
4. 보드의 학습 시간·추론 p95·최대 RAM·CPU 온도·샘플 유실 측정. Mac 수치를 보드 수치로 사용하지 않기.
5. 실제 발전기 확보 후 컨트롤러 모델·신호 정의·측정 단위와 제조사 기준을 확인해 동시 수집. 해당 장비의 정상 기록으로 새 학습.
6. 공개 엔진 미탐지 원인과 채널 선택/모델을 개선하되 이미 본 test는 탐색용으로 전환하고 새로운 독립 평가 세트를 확보. 경보 기준을 낮춰 기존 test만 맞춘 결과를 검증 성공으로 발표하지 않기.

## 그대로 유지할 경계

- 아이폰4종진동 분류 실험은 별도 증거이며 이 모델의 실제 발전기 성능이 아니다.
- 이 모델은 running 안정운전용. 시동·예열 분석, 실제 고장부위/RUL, 자동제어는 구현 주장하지 않는다.
- source=live인 숫자는 진짜 컨트롤러/IMU에서 받아야 한다. 실제 센서가 없는 값은 모의 또는 null로 남긴다.
- 운전후 학습 구조는 구현됐지만 실제 UNO Q에 설치했다는 증거는 없다.
- 원격 저장 서버 ACK/정비티켓/실제 Modbus 레지스터 어댑터는 기존 웹 팀이 추가 연결한다.
- 기존 v1 계약·iPhone 앱·미로 저장소·발표자료는 수정하지 않았다. 이 작업폴더는 Git 저장소가 아니므로 커밋/푸시는 하지 않았다.
