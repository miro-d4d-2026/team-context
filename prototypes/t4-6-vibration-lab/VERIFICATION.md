# UNO Q QWIIC 계측 검증 기록

확인일: 2026-10-10. 현재 경로는 **LSM6DS3TR-C → UNO Q QWIIC / Wire1 → STM32 MCU → Linux RouterBridge → USB ADB → 로컬 웹 화면**이다.

## 빌드와 업로드

실제 업로드용 스케치는 UNO Q에 설치된 **Arduino Zephyr 0.51.0**으로 보드에서 컴파일했다. 프로그램 22,716바이트, 전역변수 11,248바이트이며 업로드 후 실제 센서 응답을 확인했다. 먼저 수행한 로컬 코어 1.0.0 컴파일은 별도의 빌드 확인이며, 그 ELF를 구형 로더에 직접 배포한 것이 아니다.

근거: [온보드 컴파일 로그](evidence/unoq-onboard-compile.log), [업로드 로그](evidence/unoq-upload.log), [업로드 후 최초 상태](evidence/unoq-first-status.json).

## 실제 LED와 그래프 관찰

2026-10-10 사용자가 대화에서 **“LED와 그래프 모두 반응함”**이라고 확인했다. 이는 사용자의 실물 관찰 기록이다. 자동 검증의 `led_ready: true`는 MCU의 `matrix.begin()` 성공 응답이며, 이 관찰과 구분한다. 응답 지연·표시 정확도·화면 동기화 정도를 계측한 결과는 아니다.

기존 evidence 파일은 당시의 소프트웨어 확인 범위를 보존하기 위해 수정하지 않았다. 사용자 관찰은 이 문서에 별도로 추가했다.

## 웹 화면에서 확인한 동작

실제 브라우저에서 저장 기록 재생을 종료하고 실시간 화면으로 돌아온 뒤, 웹의 **연결 해제 → UNO Q 연결하기**를 확인했다.

- 연결 해제: 미연결 상태와 마지막 수신 데이터 안내를 표시하고, 축 값은 `—`, 기록 시작 버튼은 비활성화했다.
- 다시 연결: `fresh: true`와 실측 수신이 복구되었다.
- 검증 중 브라우저 오류 로그는 없었다(`[]`).

최종 API 상태는 `connected: true`, `fresh: true`, `source: unoq_qwiic`, 링버퍼 초과 0회, 읽기 오류 0회, `recording: null`이었다. 이는 웹 연결 동작의 확인이며 USB 케이블을 물리적으로 뺐다가 연결한 시험은 아니다. [실측 웹 화면](evidence/unoq-live-web.png)을 저장했다.

## 자동 테스트

현재 실행 경로의 합성 입력 테스트 **23개가 통과**했다.

- 수신·기록 서버와 게이트웨이 전송: 14개.
- QWIIC 게이트웨이: 9개.

```sh
.venv/bin/python -m unittest -v test_server.py test_gateway_transport.py
.venv/bin/python -m unittest discover -s gateway -p 'test_qwiic*.py' -v
```

형식 오류·비정상 숫자·시각 순환·순번 누락·RMS·기록 종료·CSV 재생·RPC 오류 재시도 등을 검증한다. 이 테스트는 합성 입력을 사용하며, 실제 장치 확인은 위 실측 및 사용자 관찰 근거에 따른다. 이전 BLE 시제품 테스트는 23개에 포함하지 않는다.

## 아직 확인하지 않은 범위

- Bambu Lab A1 mini의 확인된 왕복 동작, 동일 조건 반복 측정, 조건별 진동 비교. 후속 시도의 중단 상태는 아래에 기록했다.
- 센서·시간축 교정, 분석 가능한 주파수 범위 및 진동 측정 정확도 검증.
- 고장 탐지 성능, 열화 추정, 잔여수명(RUL) 예측. 현재 구현에는 이러한 판정이 없다.

현재 완료한 마일스톤은 실제 센서의 **취득 → LED·그래프 표시 → 저장 → CSV 다운로드 → 재생** 경로 확인이다.

## 프린터 실험 시도와 중단 상태

2026-10-10 오후 카메라에서 베드 앞쪽 왼편의 IMU와 가열하지 않은 대기 상태를 확인하고, Bambu Studio의 Y축 1 mm 이동 버튼을 조작했다. 그러나 카메라와 IMU에서 실제 이동을 확인하지 못했다. 10 mm 왕복 3회는 실행하지 않았다. [UI 조작 시점](evidence/a1-jog-events.json)은 명령 수신이나 실제 이동 완료의 증거가 아니다.

첫 시도 `A1mini_Y축_조그_01`과 두 번째 준비 기록 `A1mini_Y축_조그_02`는 로컬에 보존했다. 두 번째 기록 중 사용자가 GitHub 업로드로 작업을 전환하여 기록을 종료했다. 이 시도들의 원시 CSV와 프린터 카메라 화면은 이 PR에 포함하지 않았다. 두 번째 기록 시작 부근의 진동을 프린터 조그의 결과로 해석하지 않는다.
