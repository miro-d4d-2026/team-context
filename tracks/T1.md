# T1 — 자율·무인 시스템과 대드론

확인일: **2026-10-09 KST**. 공식 요구는 오늘 다시 확인한 [운영 과제집 B-2, 4–7행](https://docs.google.com/spreadsheets/d/1z-knlD7tXlieexed2eHruSseUu6dBYt3K-mT5NAbXHg/edit#gid=851891445&range=A4:J7), 연구 판단은 10/8 팀 리서치의 T1 분석과 아래 1차 자료에 근거한다. 최종 트랙은 미확정이며, 이 문서는 선택을 돕는 브리핑이다.

**우리 팀이 T1을 검토한다면 T1-1의 인간요인·감독 인터페이스부터 범위를 확인하는 편이 낫다.** 항공 분야에 대한 관심과 정비 경험은 문제를 이해하는 데 도움이 되지만, 자율비행·대드론 센서·암호 시스템의 구현 경험까지 확인된 것은 아니다. T1-2·3·4는 현재 확보한 자원만으로 하루 안에 핵심 성능을 입증하기 어렵다는 것이 우리 분석이다.

## 공식 문제 네 개와 요구 범위

아래 ‘확인해야 할 결과’는 공식 요구를 검토 항목으로 풀어 쓴 것이다. 운영진이 별도로 정한 제출 양식이나 공식 채점 세부 항목은 아니다. 예시 접근 방향을 전부 구현해야 한다는 의미도 아니다.

| 문제 | 공식 요구의 핵심 | 요구 충족을 판단하려면 확인해야 할 결과 | 과제집 SC 표시 |
|---|---|---|---|
| **T1-1 1인 다중 무인기 동시 통제** | 한 사람이 공중·지상·해상의 이종 무인체계 **3대 이상**에 임무를 부여하고 동시에 감시·통제. 인지부하를 줄이면서 임무 성공률 유지 또는 개선 | 장비 수·종류, 사람이 실제로 할 수 있는 일, 인지부하와 수행 성과를 함께 다룬 근거 | 별도 표시 없음 |
| **T1-2 산악·도심 혼재 지형 자율 드론 운용** | APAC의 복합 지형에서 지형을 고려하고 통신·전자전 제약 속에서도 임무를 지속하는 자율 체계 | 제시한 환경과 시험 조건, 자율 동작의 범위, 지속성에 대한 근거. 단순 3D 화면은 해당 성능을 증명하지 않음 | SC1 |
| **T1-3 수도권 영공 소형드론·풍선 침투 대응** | 도심 저신호 비행체에 대한 탐지·추적·식별·위협 평가·대응 결심 지원 | 각 단계에서 실제 입력과 결과가 무엇인지, 어디까지 검증했는지. 물체 분류 하나로 전체 요구를 충족했다고 할 수 없음 | SC1 + SC2 |
| **T1-4 무선침묵 환경 피아식별** | 전파 방출을 최소화한 암호학적 **2컴포넌트** 식별 체계, 중간자·재전송 공격에 견디는 방향 제시 | 2컴포넌트와 저방출의 정의, 보안 주장과 시험 범위. 일반 보드 연결 성공과 보안 검증을 구분 | SC2 |

SC 표시는 결합 안내다. 표시만으로 특별 챌린지 참가 요건을 충족하지 않으며, 실제 조건은 [공통 컨텍스트](../CONTEXT.md)를 따른다. T1 앵커에는 EDTH·Prairie Schooner·Oregon UAS Accelerator가 안내되어 있다.

## T1-1: 검토할 여지가 있는 부분

10/8 리서치는 T1 안에서는 이 문제의 사용자 적합도를 가장 높게 보았다. 핵심은 ‘장비가 많이 보이는 화면’보다 사람이 상태 변화를 이해하고 필요한 정보를 찾을 수 있는지에 있다. 그러나 **민간 장비의 기록 검토 UX가 공식 과제의 임무 부여·통제까지 충족하는지는 미확인**이다. 가상 장비 3대도 자동으로 인정된다고 가정할 수 없다.

팀이 검토할 수 있는 인접 범위는 **비무장 민간 구조·시설점검 장비의 상태 기록을 검토하는 화면**이다. 예를 들어 관측 시각, 오래된 정보, 일반 고장, 확인 담당자, 정정 기록을 구분하는 경험이다. 이 범위의 목적은 사람이 기록을 정확하게 이해하는지 살피는 것이며, 실제 비행 제어나 전투 임무 분담의 구현을 제안하는 것은 아니다.

이런 UX를 비교한다면 동일한 기록을 보고 놓친 상태 변화, 원기록 찾기 시간, 주관적 부담을 나눠 확인할 수 있다. NASA-TLX는 인간과 시스템의 상호작용에서 느끼는 부담을 여러 차원으로 평가하는 도구다. 클릭 수나 완료 시간 하나를 곧바로 인지부하라고 부르지 않아야 한다. 소수 팀원의 탐색적 시험도 실전 인력 절감이나 임무 성공률 향상을 입증하지는 않는다. [NASA TLX 공식 안내](https://www.nasa.gov/human-systems-integration-division/nasa-task-load-index-tlx/)

## T1-2·3·4: 기존 리서치가 후순위로 둔 이유

**T1-2는 UI보다 검증 환경의 부담이 크다.** 원문은 지형·통신·자율성의 결합을 요구한다. 팀에는 이를 시험할 기체, 제공 데이터, 시뮬레이터 실행 결과, 해당 분야 담당자가 확인되지 않았다. 민간 시설점검 기록의 누락·신뢰도 검토로 좁히면 작은 연구는 가능하지만, 그것으로 원문의 자율 운용 문제를 해결했다고 발표할 수는 없다. 과제 배경을 자율비행 분야 전체가 최단거리만 다룬다는 사실로 확대해서도 안 된다.

**T1-3은 관측과 의도 판단 사이의 간극이 크다.** FAA는 탐지 시스템 자체가 드론의 의도나 위협 수준을 결정하지 못한다고 설명한다. 물체를 잘 분류하는 것과 적대 의도를 아는 것은 다른 주장이다. FAA 자료는 미국 민간공항 맥락이므로 한국의 권한·규정 근거로 옮겨 쓰지 않는다. 기존 리서치가 제안한 합성 관측의 사실·추정·미확인 구분 교육 도구도 원 과제 전체와는 차이가 있다. [FAA 탐지·대응 시스템 안내](https://www.faa.gov/airports/new_entrants/uas_detection_mitigation_response)

**T1-4는 인증 성공보다 보안 주장의 범위가 문제다.** NIST의 디지털 인증 지침은 네트워크 정보시스템에서 사용자의 인증과 인증기 관리를 다룬다. 군용 IFF 성능이나 실제 대상의 의도를 보증하는 표준이 아니다. 기존 리서치의 ‘인증·식별·의도를 구별하는 비전투 교육 화면’은 이해를 돕는 대안일 뿐, 원문 핵심 체계의 구현으로 인정되는지는 별도 확인 대상이다. [NIST SP 800-63B-4](https://csrc.nist.gov/pubs/sp/800/63/b/4/final)

## 우리 자원으로 판단하면

10/9에 새로 확인된 것은 **A1 mini 보유**다. 과거 보고한 M5 MacBook Pro와 ESP32·Arduino·Pi 5는 현재 반입·동작 상태가 미확인이다. 프린터는 작은 장치 받침을 만들 수 있지만, 기체·센서 데이터·보안 검토·실험 환경을 대신하지 않는다. 기존 이동형 통신 중계 로봇도 완성된 기체나 T1 적합성이 입증된 결과물이 아니다.

현재 준비 단계에서는 T1 전체를 새로 구현하기보다, T1-1의 축소 범위가 인정되는지 먼저 확인할 가치가 있다. 인정되지 않거나 이종 3대의 의미와 평가 범위를 해결할 수 없다면, 이미 검토 중인 T4-8·T2-1과 다시 비교해야 한다. 이것은 팀의 확정 선택이 아닌 시간·증거 부담에 따른 제안이다.

## 멘토에게 먼저 확인할 질문

1. **T1-1의 이종 3대**는 어떤 종류 조합을 의미하며 가상 장비도 인정되는가? 민간 구조·점검 맥락의 감독 UX는 어느 범위까지 제출 가능한가?
2. 임무 부여·통제를 포함한 필수 범위와 사용성 연구만으로 인정되는 범위는 어디까지인가? 제공되는 시뮬레이터·기록·평가 환경이 있는가?
3. 인지부하와 수행 성과에 대해 해커톤에서 기대하는 비교 수준은 무엇인가? 소수 사용자 시험의 한계를 명시한 결과도 평가 대상인가?
4. T1-2·3에는 팀이 합법적으로 이용할 수 있는 공개·합성 데이터와 평가 기준이 제공되는가? 제공되지 않는 항목은 어떤 근거로 평가하는가?
5. T1-4의 ‘2컴포넌트’·‘무선침묵’의 정확한 의미와 요구 검증 범위는 무엇인가? 교육·보안 분석 중심 결과도 인정되는가?

문서 준비와 웹 자료 확인만 수행했으며, 장치 실험·비행·탐지·보안 검증은 수행하지 않았다.
