# T2 — 공개정보를 검증 가능한 판단으로 바꾸기

확인 기준: **2026-10-09 KST**. 공식 요구는 운영진 과제집 B-2의 8–13행을 기준으로 정리했다. 아래의 추천 순서는 팀의 시간·자원에 대한 분석이며 최종 트랙 결정이 아니다. 데이터 문서를 읽은 것과 실제 API 응답·사용 권한·앱 동작을 확보한 것은 구분한다. [공식 T2 전체 과제](https://docs.google.com/spreadsheets/d/1z-knlD7tXlieexed2eHruSseUu6dBYt3K-mT5NAbXHg/edit#gid=851891445&range=A8:J13)

지금 팀이 먼저 살펴볼 것은 **T2-1**, 다음은 조건이 맞을 때 **T2-2**다. 둘 다 하드웨어 없이 준비할 수 있지만, 자료를 모으고 요약하는 화면만으로 핵심 요구를 충족하지는 않는다. T2에서는 “이 문장을 어떤 근거로 말했는가”, “관측하지 못한 것과 실제로 없는 것을 구별했는가”가 중요하다. A1 mini는 이 트랙의 필수 자원이 아니다.

## T2-1을 고른다면: APAC 재난 발표 근거 검토

**제안하는 장면:** 일본의 과거 지진 한 건을 두고 “현재 자료에서 확인되는 규모와 발생 시각은 무엇이며, 발표가 어떻게 수정됐는가?”를 묻는다. 답의 각 문장에서 기관 원문을 열고, 숫자가 다른 이유가 수정 시각인지 측정 방식인지 확인한다. 다른 기관의 수치가 다르다는 이유만으로 어느 쪽을 오보라고 처리하지 않는다. 재난 회복력을 APAC 관심 이슈로 인정하는지는 아직 확인할 사항이다.

10/8 리서치의 추천은 유지할 수 있다. 다만 경쟁력은 챗봇이나 에이전트 수보다 **검토 가능한 근거와 판단 보류**에서 찾아야 한다. “독립 출처 두 곳”도 기관명 두 개를 적는 것으로 끝나지 않는다. 한 기관의 발표를 옮긴 기사 여러 개는 같은 주장에 대한 독립 검증이 아닐 수 있다. 수치의 정의·발행 시각·관측 시각까지 맞춰야 교차검증이 된다.

### 지금 확인한 자료 접근 조건

| 자료 | 공식 문서에서 확인한 점 | 준비에 미치는 영향 |
|---|---|---|
| USGS 지진 GeoJSON | 프로그램용 공개 피드에 사건 `time`, 수정 `updated`, 피드 `generated`가 따로 있음 | 사건 발생·자료 수정·수집 시각을 합치지 않는다. 일본 사건 자료가 실제 선택 범위에 있는지는 별도 확인. [USGS 형식 문서](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php) |
| 일본 기상청 JMA XML | 고빈도 피드는 매분 갱신하며 최근 최소 10분, 장기 피드는 매시간 갱신하며 수일 자료 제공. 중단·지연 가능성을 안내 | 과거 사건 전체 기록을 현재 피드에서 얻을 수 있다고 가정하지 않는다. 필요한 발표·정정을 확보할 경로와 이용 조건 확인. [JMA 공개 피드 안내](https://xml.kishou.go.jp/xmlpull.html) |
| GDELT DOC | 다국어 뉴스 발견과 기사 목록 제공. ArticleList는 기본 75개, 최대 250개로 문서화 | 보조 자료 발견에 사용한다. 모든 기사·SNS·원문 사용권을 확보해 주는 서비스로 해석하지 않는다. 오래된 소개 문서이므로 현재 응답 범위는 별도 시험. [GDELT 공식 문서](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/) |

이번 확인에서는 위 문서를 열어 읽었다. **팀 앱의 실제 호출, 인증, 응답 지연, 재시도, 원문 저장 권한은 시험하지 않았다.** 정부 공개 자료도 해당 자료의 출처 표시·가공 표시·제3자 권리를 확인한다. 저장된 자료를 쓰면 저장 시점을 표시하고 실시간 수집이라고 설명하지 않는다.

### 데모가 입증해야 할 것

1. **인용이 주장과 맞는다.** 링크 존재 여부와 실제 지지 여부를 따로 본다. 숫자·단위·부정·추정 표현이 원문과 일치하는지 사람이 검토한다.
2. **정정이 반영된다.** 이전 발표와 수정 발표를 함께 주었을 때 기준 시각에 맞는 답을 내고 변경 이유를 보여준다.
3. **부족한 근거를 인정한다.** 자료에 없는 질문에는 근거 부족을 표시한다. 오래된 자료만 받은 경우 최신 상황을 안다고 답하지 않는다.
4. **검토가 빨라진다.** 같은 질문과 자료를 수작업으로 확인할 때의 시간·오류와 비교한다. 소수 팀원 시험은 예비 사용성 결과로 보고한다.

첫 검토 묶음은 사건 하나, 두 언어, 원기관 두 곳, 답 가능한 질문·근거 없는 질문·상충 질문을 각각 포함하면 충분하다. 이 수량은 공식 조건이 아니라 범위를 줄이기 위한 제안이다. 신뢰도는 근거 충족·상충·미확인 같은 상태와 이유로 설명하고, 근거 없는 “87% 확실”을 붙이지 않는다. 이것이 공식 신뢰도 표기 요구를 충족하는지도 확인한다.

## T2-2를 고른다면: 합성 재난 게시물의 검토함

**제안하는 장면:** 가상 APAC 재난에 관한 합성 게시물 묶음에서 독립 제보, 정상적인 공지 재게시, 오래된 사진의 재사용, 정정 게시물을 구별한다. 사람이 원문·발행 시각·서로 연결된 근거를 확인한 뒤 검토 결과를 남긴다. 실제 개인을 악성 계정으로 분류하거나 국가 배후를 추정하는 데모로 확장하지 않는다.

여기에는 과제 적합성의 간극이 있다. **내용이 틀림, 문구가 같음, 여러 계정이 조정됨, 비진정한 운영, 특정 국가의 공작**은 서로 다른 주장이다. 합성 재난 루머 검토가 공식 FIMI/CIB 과제의 어느 부분까지 인정되는지 확인해야 한다. T2-1의 근거 검토 기능에 “허위정보 탐지”라는 이름만 붙이는 방식은 피한다.

10/8 리서치가 언급한 C2PA도 같은 주의가 필요하다. C2PA는 콘텐츠의 출처·변경 이력을 검증하는 표준이며 내용의 진실을 보장하지 않는다. 서명 부재도 위조의 증거가 아니다. 현재 팀에 검증 도구나 서명된 시험 자료가 있다는 사실은 확인되지 않았다. [C2PA 공식 설명](https://spec.c2pa.org/specifications/specifications/2.4/explainer/Explainer.html)

평가에는 정상 재게시를 악성으로 오판한 횟수, 같은 주장끼리 묶은 정확성, 서로 다른 주장을 잘못 합친 사례, 정정 반영, 근거 부족의 보류를 포함한다. 합성 자료를 만들 때 정답을 정한 사람과 결과를 확인하는 사람을 나누고, 평가용 사건·문구를 준비용과 분리한다. 합성 시험의 성능을 실제 정보공작 탐지 성능으로 보고하지 않는다. 실제 SNS로 확장하려면 API 권한·과거 자료 범위·삭제 반영·재배포 조건이 먼저다.

## T2-3~6에서 기존 리서치를 어떻게 읽을까

**T2-3:** 전후 영상의 차이는 촬영 조건·구름·계절·정합 오차일 수 있다. 변화가 보인다는 사실과 변화의 의도는 별개다. 기존 홍수 전후 비교 제안은 민간 검증 장면으로 이해하기 쉽지만 전략 거점 과제를 충족한다고 확정할 수 없다. 영상 한 쌍과 변화 정답, 변화 없는 영역의 오탐을 확인할 수 있는 팀일 때만 후보로 올린다.

**T2-4:** AIS 미수신은 고의 은닉의 증거가 아니다. Global Fishing Watch도 수신 범위·간섭·불완전한 자료 때문에 이벤트를 확정 사실이 아닌 추정 활동으로 다룬다. 공개 화면을 볼 수 있다는 사실과 데이터 사용 조건을 충족했다는 사실도 다르다. [GFW 데이터 한계](https://api-doc.globalfishingwatch.org/our-apis/documentation/docs/v3/general-api-doc/data-caveats), [접근·이용 안내](https://globalfishingwatch.org/datasets-and-code/). 기존 리서치의 넓은 해역 집계·관측 공백 설명은 인접 교육 범위이며 은닉 선박 탐지 요구 자체를 대신하지 않는다.

**T2-5:** 사건 후 보도를 입력에 포함하면 예측이 아니라 미래 정보 누출이다. GDELT의 보도량은 실제 물류량이나 행동 의도의 측정값이 아니다. 현재 확보된 자료로 특정 세력의 행동 확률을 정당하게 검증할 근거가 없으므로 우선순위를 낮춘다. 기존의 민간 재난 경보 재생안 역시 원 과제와 차이가 크다.

**T2-6:** 지도에 항적과 궤도를 함께 올리는 것보다 시각·좌표·단위·자료의 오래된 정도를 맞추는 일이 먼저다. 공개 ADS-B의 누락과 궤도요소의 갱신 주기를 확인해야 하며, 화면상 근접을 충돌 위험이나 의도적 기동으로 단정할 수 없다. 10/8 문서의 OpenSky 한도·인증 방식과 CelesTrak 형식 설명은 이번 검토에서 다시 시험하지 않았으므로 설치·연동 전에 해당 공식 문서를 재확인한다. 민항 집계나 합성 궤도 교육안으로 좁히려면 원 과제 인정 여부도 묻는다.

## 팀이 다음에 결정할 세 가지

- T2-1의 민간 재난·공공 인프라 회복력 시나리오와 근거 상태 표기가 공식 요구에 맞는가?
- 선택한 사건의 원문·정정 기록·이용 조건을 오늘 확보할 수 있는가? 없으면 사건을 바꿀 것인가?
- 실제로 보여줄 차별점을 인용 지지, 독립 출처, 정정·상충 중 어디에 둘 것인가?

현재는 **T2-1의 작은 원자료 묶음과 질문별 정답 근거를 먼저 확보하는 판단**이 가장 타당하다. 자료가 확보되지 않은 채 인터페이스부터 만들거나, T2-2~6의 이름만 추가해 범위를 넓히지 않는다. 구현·트랙 선택은 이 확인 다음에 결정한다.
