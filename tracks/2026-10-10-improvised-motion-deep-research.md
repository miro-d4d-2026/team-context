# 즉흥 모션으로 조종하기: 연속 입력·개인 동작 학습·유지보수 심화 조사

2026-10-10 KST. 상태: **T4-8 후보 심화 조사, 발산 유지. 최종 선택·구현·실기체 시험 없음.**

**후속 조사:** [현실적인 대책·오픈소스·실패 사례](2026-10-10-motion-mitigations-open-source.md)에 이 문서의 우려를 줄일 기존 방법, 도구별 관리 상태와 한계를 추가했다.

## 1. 이번에 확인한 사용자 의도

사용자는 춤·손 웨이브 같은 즉흥 동작으로 드론을 조종하는 아이디어를 제시했다. 우지가 유지보수와 불규칙한 모션에서 버그가 발생할 가능성을 언급했다고 전했다. 후속 답변에서 다음 두 의미를 모두 선택했다.

- **연속 입력:** 손 웨이브처럼 계속 변하는 움직임을 화면 속 드론이 실시간으로 따라가는 느낌.
- **개인 동작 학습:** 사용자가 즉석에서 만든 동작을 몇 번 보여주면 명령으로 배우는 느낌.

이 둘을 동시에 사용하고 싶다는 의도이며, 기존에 정한 제스처 몇 개를 춤처럼 이어 붙이는 것만을 뜻하지 않는다. T4-6·T4-8 전체 발산을 중단하거나 이 후보로 확정한 것은 아니다. 이전 [11개 장치 발산](2026-10-10-t4-6-t4-8-board-ideation.md)에서 이어지는 별도 조사다.

이 문서는 교육용 드론 시뮬레이터의 입력·인식·사용성에 한정한다. 상용 제품 설명, 실제 논문 실험, 이번 아이디어에 적용한 추론을 구분한다. 이번 행사 현직자·심사위원 인터뷰, 우리 보드의 입력·모델 실행, 신규 사용자 시험은 수행하지 않았다.

## 2. 연구 질문을 세 가지로 나누기

| 방향 | 사용자에게 약속하는 것 | 필요한 의미 정의 | 다른 방향의 성공으로 대신할 수 없는 것 |
|---|---|---|---|
| A. 연속 움직임 대응 | 내 움직임에 따라 출력이 계속 변함 | 기울기·속도·동작 크기 중 무엇이 어떤 출력 변화를 뜻하는가 | 동작 이름 몇 개를 잘 분류했다고 연속 추종 성능이 입증되지 않음 |
| B. 내가 만든 동작 등록 | 내가 정한 동작을 이후 다시 알아봄 | 동작 시작·끝, 원하는 명령, 비슷하지만 명령이 아닌 행동 | 잘라 놓은 등록 동작 정확도로 상시 입력의 오작동률을 알 수 없음 |
| C. 내 동작 방식에 맞춘 연속 대응 | 같은 의도를 내게 편한 움직임으로 표현 | 시연한 움직임과 원하는 출력의 짝, 어느 변형을 허용하고 어느 변형을 입력으로 쓸지 | 입력 동작만 보여준다고 사용자가 원한 출력 의미까지 자동으로 정해지지 않음 |

C는 A와 B를 연결해 계속 발산할 가설이다. 개인화·연속 매핑 자체에도 선행연구가 있으므로 새로운 원리라고 주장하지 않는다.

**속도·크기의 의미가 충돌할 수 있다.** 빠르게 하든 느리게 하든 같은 명령이어야 하면 속도 변화에 둔감해야 한다. 빠른 웨이브가 더 빠른 화면 움직임을 뜻하면 그 변화를 보존해야 한다. 동작 크기·방향도 마찬가지다. 어느 변형이 잡음이고 어느 변형이 의도인지는 제품의 상호작용 규칙이지, 모델 정확도 하나로 해결되는 문제가 아니다.

## 3. 선행사례와 확인 범위

이 절의 제품 기능은 제조사 설명이며 독립 성능 검증이 아니다. 논문의 참가자·과제·센서는 우리 보드·즉흥 춤과 다를 수 있다. 이름이 비슷해도 '드론과 함께 춤추기', '몸동작으로 조종하기', '사용자 동작 학습'을 구분한다.

## 4. 우지의 우려를 실패 원인별로 나누기

불규칙한 모션이 곧 소프트웨어 버그라는 뜻은 아니다. 사용자 눈에는 모두 '가끔 이상하게 움직임'으로 보이지만, 아래 원인은 다르게 고쳐야 한다. 표는 관측된 우리 제품의 오류가 아니라 앞으로 재현·측정할 상황이다.

| 보이는 문제 | 가능한 원인 | 시뮬레이터에서 구분할 근거 |
|---|---|---|
| 인사하다가 명령이 나감 | 명령/비명령 의도 구분 실패. 센서에는 등록 동작과 같을 수 있음 | 등록 동작 정확도와 별도로 컵 집기·대화 손짓·스트랩 조정 중 발행된 오명령 사건을 셈 |
| 연속 웨이브 중 개인 명령이 갑자기 끼어듦 | 두 입력 방식의 의미·전환 규칙 충돌 | 연속 조작은 의도했으나 개인 명령은 의도하지 않은 구간을 따로 표시. 춤 전체를 무조건 비명령으로 분류하지 않음 |
| 느린 동작은 되는데 빠르면 튐 | 동적 가속도, 센서 범위 초과, 누락 표본, 필터·인식기 차이 | 다른 속도·크기에서 원시 값·시간·입력 출력 관계를 비교. 필터를 강하게 하면 표현과 응답도 줄어드는지 확인 |
| 손목은 제자리인데 화면이 서서히 움직임 | 바이어스·드리프트·시간 간격 오류 | 정지 및 복귀 구간의 오차를 시간에 따라 보고, 센서 오차와 잘못된 타임스탬프 처리를 분리 |
| 벗었다 다시 차면 이전 동작이 안 됨 | 장착 위치·방향·고정 상태 변화 | 같은 사용자 재착용 전후, 보정 전후를 분리. 중립 자세 보정으로 회복되는 범위와 새 예시가 필요한 범위를 측정 |
| 만든 사람만 잘 됨 | 사용자별 속도·크기·가동범위·동작 습관 차이 | 새 사람이 정해진 등록 절차를 거친 뒤 별도 시도로 평가. 등록 전·후 성능을 구분 |
| 동작이 끝난 뒤 늦게 반응 | 동작의 끝을 기다리는 정보 지연 또는 센서·전송·추론·렌더링 지연 | 시작·끝·추론 종료·화면 반응을 따로 기록. 마지막까지 비슷한 두 동작의 구분 대기는 런타임 가속만으로 사라지지 않음 |
| 연결 복구 후 예전 움직임이 재생됨 | 세션·버퍼·구독·입력 유효기간 처리 결함 후보 | 지연·끊김·재연결을 재현하고 오래된 입력·중복 발행·첫 유효 입력까지 시간을 셈 |
| 양손의 동시 동작이 어긋남 | 서로 다른 센서 시계·샘플 주기·도착 지연 | 실제 획득 시점과 수신 시점을 구분. 같은 기준 사건을 관측한 두 기록의 정렬을 확인 |
| 새 동작을 등록하니 옛 동작이 바뀜 | 학습 경계 변화 또는 전처리·라벨·모델 버전 불일치 | 같은 원시 기록과 초기 상태·시간·난수 조건을 고정하고 단계별 비교. 수치 차이와 실제 명령 변화를 구분 |
| 자동 학습을 오래 할수록 이상해짐 | 자기 예측을 정답으로 재사용하거나 잘못 보정한 적응 | 사용자 확인 표본과 자동 생성 라벨을 구분. 이전 프로필과 변경 프로필의 이후 세션 결과를 비교 |

센서·축·시간의 근거는 [ST 6축 IMU 데이터시트](https://www.st.com/resource/en/datasheet/lsm6ds3tr-c.pdf), [Kok·Hol·Schön의 관성센서 추정 연구](https://arxiv.org/abs/1704.06053), [x-io Fusion 공식 문서](https://github.com/xioTechnologies/Fusion)다. ST 부품은 설명용 예이며 대여 보드의 정확한 부품을 확인한 것이 아니다. 통신·콜백 관련 근거는 [Zephyr LE Host](https://docs.zephyrproject.org/latest/services/connectivity/bluetooth/bluetooth-le-host.html)와 [GATT 문서](https://docs.zephyrproject.org/latest/services/connectivity/bluetooth/api/gatt.html)다. 이를 NU-87이나 Arduino 펌웨어의 동일 API 보장으로 해석하지 않는다. 표의 시험 방법은 자료를 이번 요구에 적용한 제안이다.

### 센서 정보와 사용자 의도의 한계

손목 6축 IMU는 가속도·각속도를 관측한다. 손가락 모양·손끝의 절대 3D 위치·전신 춤을 직접 읽는 센서는 아니다. 위치 적분은 오차가 누적되고, 중력만으로 중력축 둘레의 절대 방향이 정해지지도 않는다. 손목 기울기를 입력에 대응시키는 것과 손이 그린 궤적을 공간적으로 복제하는 것은 다른 약속이다. 두 IMU도 자동으로 전신 추적기가 되지는 않는다.

같은 센서 신호와 같은 맥락에 서로 다른 의도가 있다면 분류기만으로 완벽히 구분할 수 없다는 것이 우리의 추론이다. 입력을 받아들일 구간을 사용자가 표시하는 방법, 사용 맥락, 추가 관측 등을 비교할 수 있다. 그 과정에서 자연스러움·휴대성·설정 부담이 바뀐다. 특정 버튼이나 시작 제스처로 확정한 것은 아니다.

## 5. 왜 '인식률 98%'만으로는 부족한가

잘라 놓은 명령만 분류하는 시험에는 일상 움직임을 명령으로 착각할 기회가 없다. 반대로 비명령 시간이 대부분인 기록에서 항상 무반응이면 프레임 정확도만 높게 나올 수도 있다. 연속 사용에서는 명령 여부·경계·명령 종류·중복 여부를 함께 맞혀야 한다.

- [MAGIC Summoning, JMLR 2013](https://jmlr.org/papers/volume14/kohlsdorf13a/kohlsdorf13a.pdf)은 일상 동작 자료와 시간당 오작동을 다뤘다. 등록 제스처와 비슷한 일상 동작을 NULL 예시로 추가하는 비교를 수행했으며, 특정 4명·4동작 조건에서 단순 임계값보다 나은 결과를 보고했다. 모든 춤을 거부하거나 모든 일상 동작을 학습했다는 뜻은 아니다.
- [Ovadia 외, NeurIPS 2019](https://proceedings.neurips.cc/paper/2019/file/8558cb408c1d76621371888657d2eb1d-Paper.pdf)는 분포 변화에서 확신도의 신뢰성이 달라짐을 평가했다. 이 결과는 우리 IMU 오류율은 아니지만, 높은 confidence를 새 사용자·재착용·새 춤의 정확도 보증으로 쓰면 안 된다는 근거다.
- [Geifman·El-Yaniv, NIPS 2017](https://papers.nips.cc/paper_files/paper/2017/file/4a8423d5e91fda00bb7e46540e2b0cf1-Paper.pdf)는 받아들인 입력 비율과 그 안의 오류를 함께 본다. 우리 경우에도 거부된 입력을 빼고 정확도만 보고하면 안 된다. 논문의 같은 분포·독립 표본 조건에 따른 보장을 즉흥 스트림에 옮기지 않는다.
- [Dehghani 외, HAR 평가 연구, 2019 사전공개](https://arxiv.org/pdf/1904.02666)는 사람·겹치는 시간창의 상관이 평가에 미치는 영향을 다룬다. 개인화 제품은 등록 예시를 허용하되, 등록과 별도 시도·세션의 시험을 분리해야 한다.

임계값을 높이면 오명령이 줄어들 수 있지만 정답 명령도 더 거부할 수 있다. 더 오래 관찰하면 구분할 정보는 늘지만 지연도 늘어난다. 같은 모양의 비의도 동작은 '모르는 동작' 검출만으로 해결되지 않는다. 모든 불규칙 모션이 학습 분포 밖인 것도 아니다. 사용자가 의도한 자유 동작을 거부하면 그 역시 사용자 경험의 실패다.

## 6. 유지보수의 실제 비용

우지의 지적은 단순히 코드 파일이 복잡해진다는 문제보다 넓다. 개인화된 입력은 사용자별 센서 착용·예시·보정·매핑을 유지해야 한다.

| 바뀌는 것 | 확인할 부담 | 현재 열어 둔 대응 방향 |
|---|---|---|
| 착용 위치·스트랩 | 재착용 후 다시 맞추는 시간 | 반복 위치를 만드는 작은 출력 고정구, 사용자가 할 수 있는 보정 절차 |
| 사용자·동작 습관 | 설명·예시 등록·실패 수정 시간 | 개인 프로필과 공통 입력의 비교. 다른 사람이 이어 쓸 때의 비용도 측정 |
| 동작 사전 | 새 동작과 이전 동작·일상 손짓의 혼동 | 새 등록 뒤 기존 동작·비명령 기록을 함께 재평가 |
| 모델·전처리·런타임 | 어느 변경에서 결과가 달라졌는지 찾는 시간 | 원시 기록·보정·라벨·버전을 함께 보존하고 이전 프로필과 비교 |
| 자동 적응 | 실제 습관 변화와 잘못된 자기학습의 혼동 | 사용자가 확인한 수정과 자동 변경을 분리하고 되돌리기 비용 관찰 |

기록·재생 가능성은 소프트웨어 결함을 찾는 데 도움을 주지만 센서가 관측하지 않은 정보를 만들어 주지는 않는다. 보정 화면을 만들었다는 사실도 사용자 혼자 복구할 수 있음을 입증하지 않는다. 유지보수성은 개발자 개입 횟수, 등록·수정·재착용 시간, 수정 이후 기존 입력의 성능 변화로 확인할 가설이다.

## 7. Uno Q·ClikaRT·NU-40·NU-87에 적용할 때

이 절은 [앞서 확인한 공식 보드·런타임 자료](2026-10-10-t4-6-t4-8-board-ideation.md)에 따른 역할 제안이다. 센서 구성과 실제 실행은 확인 전이다.

- NU 보드+IMU: 손목/팔 등 선택한 위치의 관측·무선 전송. 두 위치가 의도 구분에 도움을 주는 가설이라면 NU-40과 NU-87을 각각 둘 수 있지만, 배터리·통신·동기화 부담도 생긴다.
- Uno Q: 입력 정리, 개인 프로필, 로컬 추론, 시뮬레이터와 비교 기록을 연결할 후보. 화면 실행 호스트는 실제 호환성을 확인해야 한다.
- ClikaRT: 호환 모델의 추론 실행 후보. 개인 동작을 학습시키는 도구·데이터·연산·컴파일 경로는 별도로 필요하다. 템플릿/DTW 같은 기준 방법이 ClikaRT에서 바로 실행된다고 가정하지 않는다. 런타임 가속과 인식 품질은 별개다. [공식 ONNX 실행 안내](https://docs.clika.io/clikart/how-to/run-an-onnx-model/)
- A1 mini: 손목 센서의 반복 장착 위치와 고정 상태에 기여할 수 있다. 춤의 움직임을 방해하거나 스트랩이 느슨해지는 영향도 확인해야 한다.

연속 입력은 고정 자세 매핑+필터와 학습 매핑을, 개인 명령은 템플릿 방식과 학습 인식기를 각각 같은 출력 조건에서 비교하는 방향으로 열어 둔다. ClikaRT를 사용하기 위해 필요 없는 신경망을 붙이는 것은 이번 문제의 차이를 입증하지 못한다. 모델을 쓴다면 같은 모델의 기준 실행과 ClikaRT 실행을 비교하고, 최적화 전후 출력 차이도 확인해야 한다.

## 8. 시뮬레이터에서 검증할 실험 설계

다음은 제안이며 수행 결과가 아니다. 숫자 목표나 참가자 수를 임의로 합격 기준으로 지정하지 않는다. 소규모 현장 시험은 탐색 결과로 보고한다.

1. **의도 라벨을 독립적으로 남긴다.** 언제 연속 조작을 했는지, 언제 어떤 개인 명령을 의도했는지, 그냥 움직였는지를 구분한다. 모델 출력으로 정답을 만들지 않는다. 과제 지시 시점과 실제 동작 시작도 구분한다.
2. **등록과 시험을 분리한다.** 사용자가 만든 동작을 등록하고 새로운 반복으로 시험한다. 예시 수별 등록 시간·오류를 비교한다. 새 사용자에게 등록을 허용하는 것은 가능하지만 시험 시도를 모델 조정에 다시 사용했다면 독립 시험으로 세지 않는다.
3. **변형과 비명령을 넣는다.** 속도·크기 변화, 미완성·망설임·이어지는 동작, 컵 집기·인사·스트랩 조정, 쉬는 구간을 포함한다. 연속 추종 중 춤은 유효 입력이면서 개인 명령 검출에서는 비명령일 수 있다.
4. **재착용·다른 세션을 분리한다.** 같은 기록의 겹친 시간창을 무작위로 나눈 점수만으로 새 사람·다른 날 성능을 주장하지 않는다. 당일 재착용과 실제 다음 날 시험도 다르게 표시한다.
5. **기준 방법과 조건을 맞춘다.** 연속 입력은 고정 매핑·필터와 학습 매핑을, 개인 명령은 템플릿과 학습 인식기를 각각 같은 출력 조건에서 비교한다. 개인화의 학습 시간에는 설명·등록·수정까지 포함한다. 스틱과 직접 비교하지 않았다면 스틱보다 낫다고 말하지 않는다.
6. **수정 뒤 과거 입력을 다시 본다.** 새 동작을 더했을 때 기존 동작과 비명령 기록이 나빠지는지 확인한다. 수정에 사용한 자료와 별도의 미래 시도 평가도 남긴다.

| 보고할 결과 | 핵심 정의 |
|---|---|
| 연속 입력 | 선언한 매핑의 독립 참조 대비 오차·지연·떨림, 불필요 출력. 사후 시간 정렬로 지연을 없앤 오차만 보고하지 않음 |
| 명령 검출 | 의도한 사건별 성공·누락·오분류·중복. 시간창 수와 명령 사건 수를 혼동하지 않음 |
| 비의도 발동 | 명령을 의도하지 않은 활동에서 실제 발행된 오명령 건수/해당 노출 시간. 총건수·관찰시간·활동을 함께 보고. 긴 정지 구간으로 희석하지 않음 |
| 거부 | 받아들인 비율, 받아들인 것의 오류, 정답 명령을 놓친 비율을 함께 보고 |
| 전체 지연 | 센서/동작부터 화면 반응까지 p50·p95. 명령은 시작→반응과 끝→반응을 구분. 획득·전송·대기·추론·렌더링을 포함 |
| 사용 부담 | 등록·추가 예시·수정·재착용 보정 시간, 포기한 동작, 개발자 도움 횟수 |
| 과제 성능 | 설명·설정부터 수행 기준 도달까지 총시간, 목표 정확도·실패, 반복 후 피로·흥미를 별도 기록 |

## 9. 현직자·심사위원에게 설명할 때

아래는 공개 연구와 공식 과제에서 도출한 예상 질문이며 실제 심사평이 아니다.

- **“왜 춤으로 조종해야 하나?”** 표현의 재미·몰입이 목적이면 그 가치를 직접 말할 수 있다. T4-8에서는 그와 별도로 초보자의 학습 시간·정확도에 어떤 이득이 있는지 확인해야 한다. 재미가 높다는 결과를 숙달이 빠르다는 결과로 바꾸지 않는다.
- **“매번 자기 동작을 가르치느니 스틱을 배우는 편이 빠르지 않나?”** 설명·등록·교정까지 포함한 총시간이 비교 대상이다. 모델 학습 버튼이 빨리 끝나는 것은 일부에 불과하다.
- **“교관이나 다음 사용자가 같은 장치를 설명·인계할 수 있나?”** 개인에게 편한 매핑과 공통 교육의 일관성 사이에 비용이 생길 수 있다. 개인 프로필을 갈아 끼우는 것이 인수인계 문제를 자동 해결하지 않는다.
- **“다른 날에도 되나? 새 동작 하나 때문에 옛 동작이 바뀌지는 않나?”** 재착용·세션·업데이트를 분리한 자료와 수정 비용으로 답한다.
- **“이미 있는 제스처 제어와 무엇이 다른가?”** 새로운 동작을 가르치고 수정하는 부담, 일상 오작동, 표현 변형의 보존 중 실제로 개선한 항목을 명시한다. 보드·AI의 존재만으로 답하지 않는다.

공식 T4-8은 IMU·무선 보드와 초보자의 학습 시간·정확도를 요구하며 시뮬레이터 시연을 허용한다. 따라서 기존 카메라/광학 연구의 결과를 참고하되 우리 IMU 입력에서 다시 확인해야 한다. 공연적 시연만으로 요구를 모두 충족했다고 해석하지 않는다. [공식 과제집](https://docs.google.com/spreadsheets/d/1z-knlD7tXlieexed2eHruSseUu6dBYt3K-mT5NAbXHg/edit#gid=851891445)

## 10. 계속 열어 둘 발산 방향

| 방향 | 보여줄 수 있는 장면 | 검증할 차이 |
|---|---|---|
| 내 웨이브에 맞춘 연속 입력 | 사람마다 편한 움직임으로 같은 가상 과제에 참여 | 고정 매핑보다 초기 조작 부담이 줄면서 표현 변화·정확도를 유지하는가 |
| 즉석 개인 동작 사전 | 사용자가 정한 동작을 등록·시험·수정 | 기존 템플릿 방식보다 가르치고 고치는 시간이 짧고 일상 오명령이 적은가 |
| 연속 입력과 개인 명령의 공존 | 춤의 흐름을 이어가며 의도한 때만 별도 명령을 표현 | 전환 혼동·출력 튐·불필요 발동을 줄이면서 자연스러움을 유지하는가 |
| 오해를 사용자가 고치는 입력 장치 | 실패한 동작과 기대 출력을 확인하고 예시를 고쳐 재시도 | 개발자 없이 수정 가능한가, 수정이 이전 동작을 해치지 않는가 |

모두 기존 연구와 겹치는 부분이 있는 가설이며 순위·선정은 하지 않았다. 우지의 우려를 검토할 때는 '불규칙성을 제거할까'보다 **허용할 표현 변화, 관측 가능한 정보, 의도 표시, 재현 가능한 실패, 사용자가 지불할 교정 비용**을 각각 질문하는 것이 구체적이다.
