# 이치 — 데이터와 분석·모델 검증

배경: 기계공학. 진동·운전 조건을 해석하고 데이터·분석 결과의 책임자가 된다. 기계공학 전공이라는 이유로 머신러닝 숙련자라고 가정하지 않는다. AI는 기존 코드와 실제 실행 환경을 확인하고 작은 파이프라인 하나를 함께 구현한다.

## 첫 목표는 링크가 아니라 실행 가능한 데이터 패키지

현재 계약은 XJTU-SY 재생의 RUL과 실제 IMU 상태 감시를 분리한다. 우선 기존 `tracks/2026-10-10-t4-6-deep-research.md` 및 계약 원문에서 XJTU 출처·검토 내용을 읽고 제작자 원문으로 다운로드 조건·단위·시간 정의를 확인한다. 링크를 찾은 것, 원본을 내려받은 것, 로더가 읽은 것을 구분한다. 임의 미러의 출처 불명 데이터를 섞지 않는다.

| 예상 | 첫 작업 | 넘길 결과 |
|---|---|---|
| 15분 | 기존 원본/다운로드 경로·약관·열/단위·운전 조건 확인 | 출처와 실제 확보한 파일 목록 |
| 20분 | CSV 하나를 읽고 베어링·기록번호·시간·축 보존 | 로더·입력 shape·오류 검사 |
| 15분 | 베어링 단위 학습/검증/평가 분리안 작성 | split 목록, 정답 파일의 위치와 정의 |
| 10분 | 첫 특징 추출 함수·실행 예시 공유 | 미로와 우지가 호출할 입력/출력 |

시간은 작업 운영안이다. 다운로드가 막히면 정확한 장애를 남기고 로더·단위 테스트·합성 입출력을 준비한다. 합성 데이터로 만든 결과는 실제 모델 성능으로 보고하지 않는다. 원본 접근을 해결하기 전에 대규모 학습을 했다고 쓰지 않는다.

## 두 분석 경로

**실물:** `raw_window` → 특징값·기준·상태·이유. 계약 원문의 RMS/첨도/FFT 정의를 따른다. 정상 기준이 없으면 calibrating, 품질이 나쁘면 unknown이다. 경고 지속·회복 정책과 기준 등록 조건은 코드/설정/테스트로 명시하며 임계값을 현장 검증값이라고 쓰지 않는다. 같은 경고 에피소드 ID의 생성·지속·저장은 우지와 한 경로로 연결한다. 통신 단절이나 unknown을 회복 증거로 삼지 않는다.

**공개 베어링:** XJTU 2축 기록 → 별도 특징 어댑터 → 첫 RUL 모델 학습·평가. Z축을 0으로 만들어 3축 raw_window로 위장하지 않는다. 가벼운 기준모델 하나와 학습모델 하나부터 비교하는 것을 운영안으로 권장한다. 모델 종류 자체보다 재실행·평가 근거를 먼저 확보한다.

같은 베어링의 인접 창을 학습·평가에 무작위로 섞지 않는다. 정규화·특징 선택·임계값 조정은 학습/검증 영역에서만 하고 평가 베어링을 보고 맞추지 않는다. 전체 수명이나 마지막 기록 번호를 모델 입력에 넣지 않는다. 시험 종료까지 남은 시간이라는 정답의 정의와 단위를 평가 파일에 명시한다. 예측값과 정답을 분리해 저장하고 최소한 오차·분할 개체·평가 조건을 남긴다.

## 미로·우지에게 줄 묶음

예정 위치는 `analysis/`, `datasets/`, `evaluations/`다. 기존 동등 구현이 있으면 먼저 재사용한다.

- 출처·체크섬·파일/축/단위/운전 조건의 manifest와 베어링 split 목록. 대용량 원본은 기본 Git 커밋에서 제외하고 접근 방법을 제공한다.
- 전처리·학습·추론 코드, 의존성, 재실행 명령, 모델/전처리 버전. 모델 파일이 크면 승인된 전달 위치와 해시를 남긴다.
- `raw_window`를 받아 계산·판정 부분을 반환하는 함수와 XJTU 추론 예시. 최종 record_seq를 임의로 배정하지 않는다.
- 평가 결과와 source_kind/is_example 구분. 아직 평가된 추론이 없으면 RUL null, 실제 XJTU 추론일 때만 계약의 RUL 객체를 구성한다.

**XJTU의 성능은 현재 발전기·208Hz IMU의 RUL 성능이 아니다.** 두 경로를 같은 모델로 바로 적용했다고 주장하지 않는다. 데이터와 환경 차이를 평가 한계에 남긴다.

## 첫 완료선과 경계

첫 입출력을 공유한 뒤 모델을 개선한다. 미로의 하드웨어 연결을 기다리느라 데이터 작업을 멈추지 않는다. 센서 펌웨어·서버/API·관제·record_seq 저장을 모두 구현하려 하지 않는다. 계약 원본이 없으면 우지에게 요청하고 데이터 확보/로더 작업은 계속한다.

검증기 통과는 형식 검증이지 모델 성능 검증이 아니다. 실행하지 않은 모델 수치, 정상으로 라벨링하지 않은 실측 기록, 합성 경고 예제를 실증 근거로 쓰지 않는다. 기록은 `updates/ichi-YYYY-MM-DD.md`에 남긴다.
