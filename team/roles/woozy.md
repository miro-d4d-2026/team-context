# 우지 — 계약·영구 저장·통신·관제

배경: 군 네트워크/통신 현업 경력. 팀에 전달한 raw_window/analysis_result v1 계약의 작성자다. 현업 경력을 서버 개발 숙련도로 단정하지 않는다. AI는 기존 코드·환경을 먼저 확인하고 한 결과의 저장부터 구현한다.

## 첫 작업: 원본 계약 공유와 결과 하나 저장

작성 시 main에는 `contracts/v1`이 없었다. 이미 로컬 또는 다른 브랜치에 올렸다면 다시 만들지 말고 위치·커밋을 공유한다. 아직 없다면 **본인이 만든 `t4-6-contracts-v1.zip`의 원본**을 `contracts/v1/`에 올린다. README·두 스키마·검증기·테스트·예시를 함께 보존한다. 다른 AI의 요약을 원본처럼 재작성하지 않는다. 원본을 찾을 수 없으면 그 파일만 요청한다.

| 예상 | 첫 작업 | 완료 증거 |
|---|---|---|
| 10분 | 원본 계약·기존 저장 코드 확인 | 사용 커밋·원본 경로·검사 명령 |
| 20분 | 로컬 DB에 예시 분석 결과 한 개 저장 | 영구 record_seq, 결과와 미전송 큐의 원자적 저장 |
| 15분 | 수신 API와 중복·충돌 응답 | 정상/동일 중복/동일 ID 다른 내용의 테스트 |
| 15분 | 가장 작은 관제 연결 | 장비 상태·이유·출처·수신 시각 표시 |

시간은 작업 운영안이다. 모델이나 센서를 기다리지 말고 원본 예시를 `is_example: true` 그대로 사용한다. 계약 검사 명령을 실제로 실행하고 결과를 기록한다. 예시의 2배 경고·RUL 숫자를 실제 분석 성능으로 표시하지 않는다.

## 두 런타임을 구분해서 구현

**노드 측 로컬 저장:** 이치의 계산·판정과 미로의 입력 식별자를 받아 최종 analysis_result를 조립한다. `(node_id, record_seq)`가 재시작 후에도 충돌하지 않도록 순번 증가·결과·미전송 큐를 단일 DB 트랜잭션에서 처리한다. 배포는 미로가 하고, 모듈 구현은 우지가 맡는다.

**관제 수신 측:** 동일 키·동일 내용이면 duplicate 확인, 같은 키·다른 내용이면 충돌로 거부한다. 실제 영구 저장 후에만 성공 응답한다. 재전송은 ID·측정 시각·내용을 바꾸지 않는다. 수신 시각·재시도 횟수는 원본 객체 밖에 보관한다. 최신 상태는 해당 node_id의 최대 record_seq로 판단한다. 순서가 뒤집힌 재전송으로 화면이 과거 상태로 돌아가면 안 된다.

기존 계약은 `POST /api/v1/records`, 정상/동일중복 HTTP 200, 충돌 409를 첫 제안으로 둔다. 이미 합의·구현된 API가 있으면 먼저 확인하며 문서만 보고 없는 서버를 있다고 가정하지 않는다. 네트워크 송신과 실제 배포는 승인된 로컬/팀 환경에 한정한다.

## 관제와 통신 상태

화면은 `health_state`, RMS 배율, 판단 이유, 품질, 출처, 마지막 수신 시각을 보여준다. 실물 IMU와 XJTU 재생 결과를 구분하고 xjtu_replay를 발전기의 실측 수명처럼 표시하지 않는다. 모델 미준비·품질 불량·연결 끊김을 정상으로 바꾸지 않는다.

관제의 통신 끊김은 last_received/별도 heartbeat로 판단한다. 노드 센서 무응답은 sensor_missing이다. 둘을 섞지 않는다. unknown·단절을 경고 해결로 처리하지 않고, 기존 경고 에피소드 상태는 원본 메시지와 별도로 보존한다. 임의의 heartbeat 필드를 v1 객체에 넣지 않는다.

## 필수 연결 시험

같은 기록 2회 수신, 같은 키의 다른 내용, 역순 도착, 서버/노드 재시작, 네트워크 단절 후 미전송 재개, unknown 또는 단절 중 기존 경고 유지, 실제 저장 전 성공 응답 방지를 확인한다. 센서/모델 테스트와 DB/API 테스트의 증거를 구분한다.

주 작성 영역: `contracts/`, `runtime/storage/`, `services/`, `dashboard/`. 이치의 특징 계산을 서버에서 별도 공식으로 다시 구현하지 않는다. 미로의 보드 수집·펌웨어를 통신 코드 안으로 복제하지 않는다. 계약 변경은 세 사람의 입력·출력과 검증기를 함께 검토한 후 적용한다.

첫 완료선은 **예시 결과 한 개가 영구 저장되고, 동일 재전송이 중복되지 않으며, 화면에서 예시로 구분되어 보이는 것**이다. 실제 IMU 결과는 다음 통합에서 교체한다. 기록은 `updates/woozy-YYYY-MM-DD.md`에 남긴다.
