# 미로 — 실제 측정과 보드 실행

배경: 전자전기. 하드웨어·펌웨어·보드 소프트웨어를 맡겠다는 본인 요청을 반영했다. 역할 선택 후 TEAM_START.md와 team/INTEGRATION.md를 함께 읽는다.

## 먼저 재사용할 것

PR #1의 검증된 경로는 LSM6DS3TR-C → UNO Q QWIIC/Wire1 → MCU → Linux RouterBridge → USB → 로컬 웹이다. 작성 시 head는 `27f16199954c5c40eceae25cc7665eed4539f098`이었다. 최신 PR 상태와 파일을 읽고 실제로 그 버전이 설치돼 있는지는 따로 확인한다.

취득·LED·그래프·CSV 저장·재생 기록은 있지만, 발전기 이상 판정·RUL·실제 프린터 비교 실험의 완료 근거는 아니다. 기존 소스가 main에 없다고 새 계측기를 처음부터 만들지 않는다. firmware 또는 보드 설정을 바꿀 때 실제 연결 대상과 영향을 먼저 확인한다.

## 첫 작업: sample → raw_window

운영안의 예상 시간이며 성공을 보장하는 일정은 아니다.

| 예상 | 작업 | 완료 증거 |
|---|---|---|
| 10분 | 현재 branch/PR, 실제 장치, sample 패킷과 계약 원본 확인 | 사용 버전·입력 샘플·미확인 항목 |
| 20분 | Linux 수집 어댑터에서 분석용 시간창 구성 | raw_window 1개, 원본 시각·순번 보존 |
| 15분 | 누락·범위·세션·실제 유효률 처리 | 합성 단위 테스트와 실물 확인의 구분 |
| 15분 | 이치·우지에게 실제 입력 전달 | 파일·생성 명령·스키마 검사 결과 |

계약 원본이 아직 공유되지 않았으면 우지에게 원본 등록을 요청하고, 기존 샘플 기록·세션/시각 조사부터 진행한다. 요약을 보고 대체 스키마를 만들지 않는다.

현재 펌웨어/게이트웨이의 설정은 208Hz·±4g이고, 계약 예시의 416Hz·832개는 합성 데이터다. 2초 창을 사용하더라도 실제 샘플 수로 만들며 832개에 맞춰 복제·보간하지 않는다. `sample_rate_hz`는 창의 장치 시각으로 계산한다. UTC 동기화를 확인하지 못하면 `measured_at: null`이다.

MCU micros 순환과 실제 재시작을 구분하고, 새 수집 세션에는 새 boot_id를 배정한다. 모르는 유실·포화 수는 null이다. 실제 읽기에 붙인 순번이 연속이라고 센서 내부 변환 유실까지 0으로 단정하지 않는다. 센서 무응답은 0으로 채운 가짜 원시 창을 만들지 않는다.

## 그다음: 분석·저장 모듈을 보드에서 실행

이치의 분석 함수를 연결하고 우지의 저장 런타임에 결과를 넘긴다. 영구 record_seq·미전송 큐·API는 우지 코드의 책임이다. 모델 학습과 RUL 정답 작성은 이치 책임이다. 보드에 연결할 때 전처리 버전, 입력 형태, 추론 시간·메모리, 오류 전달을 확인한다.

기존 MCU/웹의 벡터 RMS와 계약 RMS는 다르다. 계약 특징 추출을 이치의 공통 함수로 일원화하고 **해당 raw_window의 샘플로** 계산한다. 표시용 LED 눈금을 고장 경고 임계값으로 쓰지 않는다. ClikaRT 채택·실행은 별도 확인 대상이며 설치 안내를 받았다는 이유로 실행 완료로 쓰지 않는다.

## 쓰기 경계와 종료 조건

주 작성 영역: `runtime/hardware/`, 기존 `prototypes/t4-6-vibration-lab/`. 계측 UI의 입력 표시까지만 담당하고 관제 화면을 별도로 다시 만들지 않는다. 계약 변경은 우지, 분석 공식 변경은 이치와 먼저 맞춘다.

첫 종료 조건은 실측 raw_window 하나의 계약 검사 통과다. 다음 종료 조건은 **그 창을 분석한 결과가 DB·관제까지 같은 식별자로 이어지는 것**이다. 품질이 invalid라면 unknown이 정답이며, 보기 좋게 normal로 바꾸지 않는다. 기록은 `updates/miro-YYYY-MM-DD.md`에 남긴다.
