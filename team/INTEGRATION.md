# T4-6 연결 경계와 통합 완료 기준

이 문서는 우지가 팀에 전달한 계약 v1의 핵심 규칙을 연결 작업에 맞춰 정리한 것이다. **정식 스키마·계산 정의·검증 코드는 `contracts/v1` 원본을 사용한다.** 원본이 아직 공유되지 않았다면 요약으로 새 계약을 만들지 않는다. 아래 함수 이름·폴더·시간 배분은 구현을 돕는 운영안이며 기존 계약의 새 필드가 아니다.

## 책임 흐름

```text
미로: 실제 IMU → 수집 어댑터 → raw_window
이치: raw_window → 특징·기준·상태·판단 이유
우지: 분석 부분 + 입력 식별자 → 영구 record_seq + analysis_result + DB/미전송 큐
우지: 수신 API → 관제
미로: 위 수집·분석·저장 모듈의 보드 배치와 통합 확인

이치: XJTU 원본 → 특징 → RUL 추론·별도 평가
우지: xjtu_replay analysis_result → 공개 데이터 평가 화면
```

외부 전달 형식은 raw_window/analysis_result 두 개다. 내부 분석 함수의 반환값은 최종 wire 메시지와 구분하며, record_seq를 분석 함수에서 임시로 배정하지 않는다. 이치가 상태/기준/경고 에피소드 변경을 결정하고 우지가 필요한 지속 상태와 결과를 원자적으로 보존하도록 맞춘다. 계약의 warning_event_id 의미를 담당자별로 다르게 구현하지 않는다.

## 처음부터 같아야 하는 계산·식별 규칙

- 가속도 단위 g, 원시 창은 중력/평균을 제거하지 않은 xyz다. XJTU는 별도 xy 어댑터이고 가짜 Z축을 채우지 않는다.
- 계약 RMS는 `sqrt((var_x + var_y + var_z) / 3)`이며 축별 평균 제거와 분모 N을 사용한다. XJTU는 축 개수 2로 나눈다. 기준도 같은 축·정의를 사용한다. PR #1의 벡터 RMS인 `sqrt(var_x + var_y + var_z)`를 그대로 넣지 않는다. 다른 시간창의 표시값을 단순 비례 환산해서 전달하지 않는다.
- 첨도는 축별 Pearson 첨도의 평균이다. FFT는 유효 대역과 시간 품질을 확인한 뒤 평균 제거/Hann 창/축별 전력 합의 최대 비DC 빈으로 계산하며, 확인 전에는 null이다.
- raw_window는 `(node_id, boot_id, window_seq)`, analysis_result는 `(node_id, record_seq)`로 식별한다. MCU/수집 앱 재시작은 새 boot_id이며 여러 세션을 같은 창에 섞지 않는다.
- 실제 sample_rate_hz는 해당 창의 sample 시각으로 계산한다. 호스트 수신률·센서 설정률과 구분한다. 416Hz·832개는 합성 예시이지 실측 보드 요구값이 아니다.
- UTC를 모르거나 추가 센서를 측정하지 않았으면 null이다. 원본 서버 수신 시각을 measured_at으로 둔갑시키지 않는다.

## 품질·상태·RUL

유실/포화가 있거나 해당 수를 모르거나 시각을 복원했다면 v1의 보수적 정책에 따라 품질 invalid, 상태 unknown을 사용한다. sensor_missing에는 input_window가 null이며 가짜 0 파형을 만들지 않는다. 정상 기준 미수집은 calibrating, 검증하지 않은 경고 임계값은 설정/운영안으로 표시한다.

실물 RUL은 null이다. 공개 데이터에서 실제 평가된 예측이 있을 때만 xjtu_replay의 RUL을 채운다. 예측 대상은 bearing_test_endpoint, 단위 min, 데이터셋 XJTU-SY다. source_ref의 원본 record 번호와 as_of_minute=record 번호−1을 유지한다. 정답/마지막 기록 번호는 추론 메시지에 넣지 않는다. 평가 범위 exploratory와 모델·전처리·평가 ID를 보존한다.

is_example=true 또는 source_kind=scenario인 데이터는 실제 성능 자료가 아니다. 프린터 조건 변화나 연결 확인 기록을 고장 정답으로 사용하지 않는다.

## 통합 단계와 담당

| 단계 | 담당·입력 | 완료 증거 |
|---|---|---|
| 1 | 우지: 계약 원본 공유 | 원본 파일·실제 검사 로그. 이 문서만으로 검사 통과 아님 |
| 2 | 미로: 실물 raw_window 한 개 | 원시 파일·수집 버전·식별자·품질·검사 |
| 3 | 이치: 해당 창 분석 | 계산 함수·동일 원시 창과 특징 대응·모델/규칙 버전 |
| 4 | 우지: 결과 저장·전송 | 영구 순번·중복/충돌·역순·재시작·단절 복구 시험 |
| 5 | 미로+우지: 실제 경로 관제 | 원시 창부터 화면까지 추적, 예시 표시와 분리 |
| 6 | 이치+우지: XJTU 평가 연결 | 모델·분할·평가표·실제 예측 JSON·별도 화면 |

형식 검사, 합성 테스트, 실물 계측, 모델 평가, 군 현장 유효성은 각각 다른 증거다. v1 검사 통과를 발전기 고장 예측 정확도로 표현하지 않는다.

## 병렬 개발에서 막히지 않는 방법

미로는 현재 sample 스트림으로 창 구성과 시각 처리를, 이치는 공개 데이터 확보·로더를, 우지는 예시 저장·화면을 독립적으로 시작한다. 본인 입력이 없으면 합성 테스트를 명시적으로 사용하되 실물 성공이라고 보고하지 않는다. 함수 이름·파일 위치·호출 예시는 첫 60분 안에 본인 updates 파일로 공유하는 것을 운영안으로 둔다.

새 실험 장치·팬·제스처 아이디어로 발산하지 않는다. 완성 모델을 기다려 세 모듈을 마지막에 연결하지 않는다. 기존 작업이 더 진행됐다면 완료선을 다시 확인하고 다음 미완료 단계로 이동한다.
