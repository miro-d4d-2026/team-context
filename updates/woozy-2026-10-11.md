정비사에게 학습·보정·검증 역할이나 모델 종류를 고르게 하지 않습니다. 시스템이 같은 장비·설치·출처의 승인 기록을 운전 회차별로 나눕니다. 정상만 충분하면 정상 모델을, 비정상도 충분하면 분류 모델까지 생성합니다. 재학습은 같은 절차를 누적 자료로 다시 실행합니다.

## 실제 구현과 보존

- 현재 UNO Q에서 IMU 수집·진동 특징·판단·웹 API 수행. Mac은 화면과 USB 연결 담당.
- 기존 실측 정상 기준·고정 모델 및 운영 기록 유지. 개인 기준과 실제 운영 DB는 GitHub에 게시하지 않음.
- 새 모델은 NumPy 조건부 회귀/잔차 코어와 이차 로지스틱 분류기. 새 분류기가 CLIKA로 실행됐다는 의미가 아님.
- 사용자 제공 다섯 메뉴 디자인을 유지하고 운전 현황을 한 화면으로 정리.
- 당시 모델과 판단·사람 검토·점검 조치를 별도로 보존.

## 추가 완료 · 실측 검토와 모델 적용

- 아이폰 자극을 확인하며 별도로 수집한 실측 4회에서 정상 132창·강함 68창·간헐 68창을 검토. 시작·전환 구간 제외.
- UNO Q에서 정상 기준과 정상·비정상 분류기를 실제 학습·평가·적용. 1·2회 학습, 3회 보정, 4회 후보 평가로 회차 분리.
- 후보 평가: 정상 기준 범위 이탈 1/33, 분류기 정상 오분류 0/33·비정상 검출 34/34. 같은 부착 환경의 별도 1회 평가로 일반 정확도 주장은 하지 않음.
- 적용 후 새 5회차: 선택한 안정 구간에서 기준 6/6창 정상, 강함 6/6창·간헐 6/6창 점검 권고. 보고서와 구간 검토 저장.
- 기존 수신 기록도 검토했지만 설치·조건 및 길이가 달라 이번 학습에 혼합하지 않음. 기존 기준·고정 모델 해시 유지와 보드 백업 완료.
- 미사용 수동 역할 선택 코드 제거, 구간 검토 집계 개선, 새 운전의 조건 자동 제안, 좁은 화면의 학습 진행 칸 수정. 이번 JavaScript 검사 160개 통과. 위 Python 270개는 이전 검증 이력.

공개본에는 코드·집계 결과만 포함. 실측 운영 DB와 개인 학습 모델 계수는 보드에 보존. [실측 학습 결과](../apps/genguard-integrated-v7/LIVE_LEARNING_RESULT.md)와 [현재 상태](../apps/genguard-integrated-v7/CURRENT_STATUS.md)를 참고.

## 운전 모드 명칭과 온디바이스 배치 확인

상단을 모의 운전/실측 운전으로 정리하고 기존 과거 파일 재생은 분석 보고서의 ‘과거 진동 재생’으로 이동했습니다. 원본·모델·검토 기록은 보존했습니다. JavaScript 161개 통과 및 실제 브라우저 재생 진입·구간 이동·실측 복귀를 확인했습니다.

UNO Q 웹 서버·IMU 수신·분석·DB 저장과 Mac의 ADB 터널을 확인했습니다. 지연으로 종료된 수신기는 DB 백업 후 서버와 재시작했으며 기존 정상 기준을 재학습 없이 복원했습니다. 모델 2개·운전 기록 8개가 동일합니다. 새 검토학습 모델은 운전 기록 중 적용하고, 기록하지 않을 때는 기존 부착 기준을 사용합니다. 부팅 자동 시작 및 별도 전원으로 USB를 분리하는 시험은 아직 없습니다.

## 상시 ML 판단 · 운전 보고서 분리 · 전원 자동 시작

기록 버튼과 무관하게 새로운 IMU 창마다 UNO Q의 적용된 정상 기준·라벨 분류 모델을 실행하도록 변경했습니다. `보고서 기록 시작/종료`는 운전 구간·당시 판단을 저장하는 기능이며 상시 감시를 멈추거나 연속 경고를 초기화하지 않습니다. 센서 조건과 일치하는 활성 학습 조건이 하나일 때 자동 연결하며, 모호한 조건·입력 단절·재시작 이전 결과는 판단 보류로 처리합니다.

실측 확인: 기록 없이 기준 진동 5/5창 정상 유사, 강함 7/7창 및 간헐 7/7창 점검 권고·비정상 유사. 별도 보고서 5창을 저장해 기존 8개+신규 1개, 총 9개 기록을 보존했습니다. 모델 2개와 계수·기존 기준 파일·고정 모델 파일은 불변입니다. 동일 아이폰 부착 시연 결과이며 실제 발전기 정확도 수치가 아닙니다.

사용자 서비스 `genguard.service`와 linger로 자동 시작을 설치했습니다. 사용자 USB 전원 분리·재연결 후 부팅 ID 변경, 수동 서비스 시작 없이 자동 실행, fresh 실측 수신과 모델 ID 복구를 확인했습니다. Mac에서는 화면 접속용 USB 터널만 다시 열었습니다. 수신기 종료 시 소유한 앱 묶음을 재시작하며 다른 프로세스는 종료하지 않습니다. 외부 보조 전원으로 Mac과 분리한 채 장시간 운용하는 검증은 별도입니다.

전체 Python 282개, JavaScript 163개, 별도 배포 검사 11개 통과. 초기 자동 시작에서 발견한 부모 프로세스의 NumPy 검색 경로도 수정하고 회귀 검사를 추가했습니다. [현재 상태](../apps/genguard-integrated-v7/CURRENT_STATUS.md), [자동 시작 안내](../apps/genguard-integrated-v7/deployment/AUTO_START.md), [확인 집계](../apps/genguard-integrated-v7/verification/continuous-monitor-check.json)를 참고하세요. 운영 DB·개인 모델 계수·실측 원본은 게시하지 않습니다.

## PC 이동·USB 재연결용 접속 도구

전원 이동 후 보드 자동 시작과 PC 화면 접속은 별개이므로 Mac 더블클릭 접속 도구를 추가했습니다. 특정 팀 보드 연결 → 부팅 대기 → UNO Q health 확인 → 브라우저 열기 순서이며 창을 유지하면 USB 재연결을 복구합니다. 다른 포트 점유를 강제로 해제하지 않고 9883~9889에서 연결합니다. 6개 격리 검사와 현재 Mac/실제 UNO Q에서 접속 터널 제거 후 실행 파일의 복구 확인을 완료했습니다. 다른 팀원 Mac/Windows 실물 확인은 아직입니다. Windows는 공식 ADB 수동 접속 안내만 제공합니다. 모델·DB·보고서를 덮어쓰거나 새 PC에 서버를 설치하지 않습니다.
