# GenGuard 감시 항목·정상 기준·AI 역할 결정안

작성: 2026-10-10. 군 구매요구서 7쪽, Cummins 공식 사양/운용/서비스 문서, scikit-learn 공식 자료를 확인했다. **연구·구현 기준 제안이며 기존 웹/UNO Q 런타임에 적용된 업데이트가 아니다.** 기존 v1 파일은 변경하지 않았다.

## 결정

**군 요구 감시·보호 항목은 모두 지원하고, 발전기별 정상 운전 기록을 이용한 변화 탐지를 더한다. 판단은 `기존 보호 경보 + 문서/운영 규칙 + 조건을 고려한 학습 모델`로 구성한다.**

Isolation Forest는 비교할 만한 온디바이스 모델이다. 하지만 그것 하나로 안전 한계, 고장 원인, 시계열 추세, 수명을 모두 해결할 수는 없다. 현재 이미 만든 조건부 회귀+잔차 분석 모델을 유지하면서 **조건 보정 잔차 Isolation Forest**를 비교 후보로 둔다. 지금 모델을 바꿔야 한다는 근거는 확보되지 않았다.

## 2. 군 요구에서 반드시 포함할 내용

구매요구서 3~4쪽 3.4.3의 표시 기능은 다음과 같다.

- 교류 전압, 교류 전류, 주파수(회전계 겸용 가능), 누적 운전시간.
- 예열 표시, 윤활유 압력, 냉각수 온도, 배터리 충전계.
- 상전압/상전류 선택 위치도 함께 저장한다. 전압값이 어느 상/어느 선간인지 알아야 해석할 수 있다.
- 콘센트, 운전반 종류, 시동 스위치 형태는 장비 설정/점검 항목에 남긴다. AI 숫자 입력으로 만들지 않는다. 해당 항목과 성능시험은 `army-coverage.json`에서 별도 자산/검사 기록으로 생성한다. 61개 감사항목은 감시 센서61개라는 뜻이 아니다.

필수 보호 기능은 별도로 노출한다.

| 군 요구 | 문서 기준 | 의미 |
|---|---|---|
| 과속 | 정격 속도 110%, 10초 이내 | 경보+기관 정지. 1800rpm 기준1980rpm |
| 저유압 | 0.6kg/cm² 이하, 1분 이내 | 경보+기관 정지. 원문 표기 보존; kgf/cm² 해석시 약0.5884bar |
| 냉각수 과열 | 95~100℃, 1분 이내 | 경보+기관 정지. 정상 온도 범위가 아님 |
| 과부하 | 연속 정격출력110% 이상, 1분 이내 | 회로 차단. 기관 정지와 다른 사건 |

이것은 납품 요구사항이다. 앱의 경보 유예시간이나 모든 발전기의 설정값으로 복사하지 않는다. 실제 보호장치 상태를 수신한 이벤트와 GenGuard가 숫자로 추정한 기준 초과도 구분한다. 기존 보호기는 그대로 유지한다.

기본 사양은 3상4선, 60Hz, 1800rpm, 연속정격10kW 이상, 120/208V 또는240/416V다. **예시 화면의 380V를 이 군 프로필 기본값으로 두면 맞지 않는다.** 배터리 충전계는 종류·단위가 미지정이며, 전압계라고 단정할 수 없다. 디지털 운전반을 허용하지만 디지털 통신/Modbus/CAN을 요구하지 않는다.

성능시험 항목도 빼지 않았다. 전압·주파수 변동/안정/과도응답, THD, 절연저항, 상평형·불평형, 소음·환경·내구시험은 `검사 기록` 화면에 둔다. 단순 실시간 IMU나 저속 전압값으로 측정했다고 표시하지 않는다. 특히 55~65Hz는 **조정 가능 범위**, 2% 밴드폭은 **±2%가 아니다**. 본문 무부하 소음시험과 표1 부하시 표기는 상충하여 확인 필요로 보존했다.

## 3. 실제 시연 기준 제품과 정상값

참조 제품은 **Cummins Onan 7.5HDKAL-1, 60Hz 모델**이다. 앞서 만든 패키지와 연속성을 유지하며 공식 정상 계기 범위가 공개되어 있기 때문이다. 군 구매요구에 적합한 납품 모델이라고 주장하지 않는다. 모델군 운용/서비스 문서는 HDKAL Spec B-J를 포함하며, 실제 제조번호·사양문자는 확보하지 않았다.

**군 조달 요구 프로필과 Onan 시연 프로필은 별도다.** 7.5kW 단상 제품의 보호값을 군10kW3상 장비에 적용하지 않는다.

| 항목 | 문서에서 확인된 기준 | 구분/주의 |
|---|---|---|
| 회전수 | 1800rpm | 정격. 실제 정상 평균/허용오차 아님 |
| 주파수 | 60Hz | 정격. 경보 범위 별도 |
| 출력 | 7.5kW | 사양서 intermittent 정격, 환경별 저감 조건 있음. 군 연속정격과 다름 |
| 전압 | 120/240V 단상 | 실제 결선별 계측 위치 확인 |
| 전류 | 120V62.5A / 240V31.3A | 각 구성의 정격. 정상은 부하에 따라 달라짐 |
| 냉각수 온도 | 71~91℃ | 부하·외기온에 따른 정상 계기 범위. 운용 인쇄8/PDF12 |
| 오일 압력 | 194~442kPa = 1.94~4.42bar | 정상 운전온도 조건. 운용 인쇄7/PDF11 |
| DC 계통 전압 | 12.5~15V | 배터리 상태/충전상태에 따라 달라짐. 운용 인쇄8/PDF12 |
| 운전 중 충전 점검 | 13.5~15V | 서비스 인쇄3-1/PDF19. 위 DC 범위와 측정 조건 분리 |
| 전압 조정 성능 | 무부하~정격 ±2.5%, 일정 부하 ±1% | 성능 사양. 자동 경보 임계값 아님 |
| 냉각수 고온 정지 | 106℃ | 해당 모델 문서 참고. 군95~100℃와 혼합 금지 |
| 저유압 정지 | 운용0.97bar / 서비스0.62bar | **문서 불일치. 운영 설정값 미확정** |
| 진동 | 공통 g 정상 범위 없음 | 설치 위치·고정·RPM·부하·수집 설정별 기준 측정 |
| 오일 온도·연료압·냉각수압 | 선택 모델의 운전 정상 범위 미확보 | 압력 위치/센서/회로별 확인. 다른 데이터셋 평균 전용 금지 |

공개 설명서에서 확인한 것은 범위/정격이며 **여러 실제 장비의 통계 평균은 아니다**. 시연의 냉각수80℃·유압3.2bar·진동0.10g 등은 우리가 고른 합성 기준값이다. 평균값이라고 발표하지 않는다. OEM 기준, 장비 실측 분포, 시연 설정이라는 출처를 별도로 저장한다.

## 4. 추가 점검과 무엇을 학습할지

표시·수집 항목 전체를 하나의 ML 입력에 전부 넣는 방식은 권하지 않는다.

| 역할 | 이번 선택 | 처리 |
|---|---|---|
| 먼저 학습할 목표값 | RPM, 냉각수온, 유압, 출력전압, 진동RMS, 진동 시간변동CV | 같은 발전기의 정상 관계 학습 |
| 조건부 추가 목표값 | 전류, 독립 측정 주파수, 배터리 전압, 표면온도 | 실제 채널/품질 확보 후; 전력·RPM과 중복 가중 주의 |
| 정상 상태를 설명하는 조건 | 부하율, 외기온 | 예: 같은50%부하·25℃ 환경끼리 비교 |
| 분석 허용 여부/정렬 | 정지·시동·예열·안정운전 구분, 실제 시동 시각, 데이터 나이, 센서 위치 | 정상 모델과 다른 단계면 판정 보류 또는 별도 모델 |
| 규칙과 이벤트 | OEM 경보·차단, 연료부족, 통신두절, 정비주기 | 숫자 이상 모델에 맡기지 않음 |
| 수동 점검표 | 오일/냉각수량, 누설, 필터, 벨트, 단자·배선, 고정 상태 | 점검 여부/발견/조치/사진/시간 기록; 미점검을 정상으로 채우지 않음 |

현재 v1은 목표7개(RPM·냉각수·유압·전압·전류·RMS·CV), 조건2개(부하·외기온)를 구현했다. 위 표는 차기 학습 입력 선택 기준이며 v1을 변경한 것은 아니다. 첫 적용은 현재 프로필을 유지한 후 전류 중복 여부를 별도 검증한다. 실제 엔진 시작시간은 수집 시작시간과 다르므로 v1의 수집 `elapsed_s`를 엔진 운전시간이라 넣지 않는다.

추가할 일반 점검 항목과 필요한 신호:

| 추가 항목 | 이유 / 신호 확보 |
|---|---|
| 연료 잔량·주유 이력 | 원래 사용자 경험의 연료 고갈 방지. 탱크 수위계/입력 필요; 진동으로 잔량 측정 불가 |
| 오일량·냉각수량 | 압력/온도 정상과 액량 정상은 별개. 레벨 스위치 또는 수동 점검 |
| 연료·오일·냉각수·배기 누설 | 제조사 일반점검 항목. 사람이 확인하거나 전용 검지기 필요 |
| 배터리 상태·충전·시동 소요시간 | 시동 불량 변화. 전압 측정 및 시동/운전 타임스탬프 |
| 공기필터·흡기 제한·통풍·라디에이터 | 출력/온도 변화 때 확인할 후보. 수동 점검 또는 제한/차압센서 |
| 냉각팬·벨트·호스 | 마모·이완·손상·누설 점검 |
| 연료필터·수분 분리기 | 수분/막힘 점검·교환 이력. 제품별 장착 여부 확인 |
| 볼트·방진마운트·배선·단자 | 진동 변화·전압 이상과 관련된 점검 후보 |
| 부하kW·역률·상별전압/전류 | 정상 비교의 조건과 전기 출력 품질. 지원 전력계/기존 컨트롤러 활용 |
| 국소 표면온도 | 접촉 RTD/열전대 등 추가 시 특정 위치 변화 비교. 냉각수 온도와 다른 항목 |
| 운전시간·달력·정비이력 | 다음 정비시기 안내. 오일 교환일까지 남은 시간과 고장까지 RUL은 별개 |
| 전원/ATS/감시노드 상태 | 선택한 Onan 기본사양으로 가정하지 않음. 설치된 전원체계 어댑터/접점이 필요 |

제조사 정상점검/교환 주기의 상세와 조건은 `manufacturer-audit.md`에 있다. 환경·사양·보증 조건에 따라 주기가 달라지므로 여기서 군 전체의 보편 주기로 제시하지 않는다.

지금 보유 IMU로 실측 가능한 것은 진동이다. 주변온도·습도(AHT20 표시)는 센서 보유/연결이 확인되지 않았고, IMU 내부 온도도 냉각수·표면온도를 대체하지 않는다. 다음 하드웨어 우선순위는 **실제 컨트롤러 신호 접근 확인 → 없으면 절연 계측 어댑터 → 외기온/국소온도 → 연료수위**다. 압력·온도 센서를 더 사기 전에 설치 발전기에서 무엇을 읽을 수 있는지 확인한다.

발전기 전원이 끊긴 뒤에도 알림을 보내려면 UNO Q/통신에 독립 또는 보조 전원이 필요하다. 저장 후 재전송만 구현해 놓고 마지막 순간의 즉시 알림까지 보장한다고 하면 안 된다.

## 5. 확정할 시연 흐름

모의 기준: Onan 참조, 안정 운전·50%부하·외기25℃, RPM1800, 주파수60Hz, 냉각수80℃, 유압3.2bar, 전압240V, 진동0.10g. **모두 합성 기준점**이다.

| 버튼/실험 | 변경 | 표시할 결과 | 담당 판단 |
|---|---|---|---|
| 정상 | 기준값 유지 | 관측한 항목에서 기준 이탈 없음 | 규칙+모델 |
| 실제 진동 변화 | 실제 IMU 입력; 나머지 모의값 | 진동 변화 감지, 부착/접촉/고정 상태 점검 | 기준 비교/학습; hybrid 표시 |
| RPM 편차 | RPM1950, 독립 주파수65Hz | 회전수·주파수 편차 점검 | ±5% 시연 규칙 |
| RPM 정상·과열 | RPM1800, 냉각수96℃ | RPM 기준 이탈 없음 / 냉각수 범위 초과 / 종합 주의 | 문서 범위+가정 지속조건 |

| OEM 경보 | 실제/모의 원천 표시한 저유압 이벤트 | 기존 보호기 경보 우선 표시 | 이벤트 규칙 |

| 데이터 중단 | 마지막 정상값 이후 stale | 현재 판단 불가 | 품질 규칙 |
| 예열 | 냉각수35℃, warming_up | 정상운전 모델 판정 대기 | 단계 구분 |
| 새 부하 | 학습 이력 없는90% 부하 | 학습조건 부족 | 지원 영역 확인 |
| 센서 불일치 | RPM1950인데 독립 주파수60Hz | 계측/시각/연동 점검 | 물리 관계 검사 후보 |
| 점검 간 추세 | 동일10분 시점의 온도79→80→82→85→89℃ | 최근 점검 온도 상승 추세 | 조건 맞춘 요약값 변화 탐지 |

Onan의96℃와 군 과열95~100℃를 같은 상태로 표시하지 않는다. 범위와 경보는 **선택 프로필**이 결정한다. 1950rpm/60Hz를 동시에 만들어 기계적 과속이라고 발표하지 않는다. 직접 구동4극 동기계에서는 독립 측정값의 불일치를 우선 의심해야 한다.

`demo-scenarios.json`의 `expected_ui`는 **설계한 기대 결과**, 실행 완료 증거가 아니다. 일부 모델 후보/추세 기능은 v1에 아직 구현되지 않았다. 실측 진동+모의 발전기 입력으로 학습한 모델은 hybrid 실험용이다. 실제 발전기의 물리 상관관계 검증으로 인정할 수 없다.

## 6. Isolation Forest와 AI의 자리

1. **안전/문서 규칙**: 정해진 기준 초과와 기존 보호 경보는 확정적으로 표시한다. AI 점수가 정상이어도 없애지 않는다.
2. **상태 패턴 모델**: 정상으로 검토된 기록에서 같은 부하·외기온의 예상값과 공동 변화를 배운다. IF는 이상한 조합을 찾는 후보지만 각 특성값을 그대로 넣으면 부하 변화와 고장을 혼동하거나 약한 상관 변화는 놓칠 수 있다.
3. **점검 간 추세**: 동일 운전시점/조건의 온도, 압력, 안정화시간을 비교한다. 시계열 특징·추세 로직을 별도로 만들지 않은 pointwise IF에는 시간 순서 이해가 없다.
4. **설명**: 현재값·문서범위·기대값·변화량·지속시간·점검 후보를 템플릿으로 만든다. LLM은 없어도 된다. 기여한 특징이 고장 원인 확정은 아니다.

이번 합성 비교는 `ai-study/AI_DECISION.md` 및 `results.json` 참조. 원시 IF와 조건 보정 후 IF의 차이를 재현했다. **기존 공개 엔진 평가에서 v1이 보류한 고장 실험3개를 모두 놓친 사실도 유효**하다. 합성 실험을 잘 통과했다고 실제 발전기 고장 성능을 확보한 것은 아니다. (`../genguard-edge-v1/EVALUATION.md`)

UNO Q의 Linux MPU에서 정상 기록을 모아 운전 종료 후 학습하고 다음 운전에서 추론하는 구성은 적절하다. MCU는 일정한 센서 수집을 맡는다. 4GB RAM에서 작은 표형 모델은 검토할 만하지만 실기기 전체 메모리/속도는 아직 측정하지 않았다. 원시208Hz를 몇 주치 메모리에 쌓기보다 2초 특징과 원시 일부 구간을 저장하며 세션/표본 수를 제한한다.

학습 순서: 정상 검토된 운전 누적 → 운전 단위 학습/보정/검증 분리 → 새 후보 생성 → 새 정상 기록의 오경보 및 별도 이상 시험 확인 → 새 운전 시작 전 활성화. 매번 나온 데이터를 자동으로 정상 편입하지 않는다. 최초 정상 모델을 보존해 완만한 열화를 새 정상으로 흡수하는 것을 견제한다. IF의 `warm_start`를 온라인 정상학습으로 오해하지 않는다.

검증 지표는 운전당 지속 오경보, 주입/관찰된 변화 이후 탐지 지연, 판정 불가 비율, 놓친 시험 수다. 같은 운전의 수천 창을 섞어서 독립 실험 수라고 세지 않는다. 목표/경보/고장 라벨을 모델 입력에 넣지 않는다.

## 7. 미로에게 넘기는 파일의 상태

이 폴더는 **검토 가능한 연구 스펙과 시나리오**다. `spec/*.json`은 새 연구 스키마이고 v1 runtime drop-in 파일이 아니다. v1 프로필/DB를 직접 덮어쓰지 않는다. `MIRO_HANDOFF.md` 순서로 필드/프로필/배지/판단 결과를 연결하면 된다.

정상/주의/경보와 `미연결·판정불가·미점검`을 함께 설계한다. 전체 화면을 초록색으로 만드는 대신 `관측 중8개·미연결5개·점검필요1개`처럼 범위를 보여준다. RUL/고장부위 확정/발전기 정확도는 검증 전 수치로 채우지 않는다.
