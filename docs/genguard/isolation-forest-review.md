# 첫 Isolation Forest 후보 검토 — 유리하지 않은 결과도 보존

## 이 시험에서 새로 한 일

제공된 `data/repeat.json`의 **기준 연속 진동**만 참조 학습에 사용했다. 1·2회차의 2초 창 8개로 64트리 Isolation Forest를 학습하고, 3회차의 4개 창으로 경계를 정했다. 학습과 경계 보정 모두 하나의 첫 녹화 내부이며 독립 운전 3회가 아니다.

입력은 기존 정의의 자연로그 합성 RMS와 100ms 세기 변동 CV다. 라벨, 시간, 회차, 재생 순서를 모델 특징으로 넣지 않았다. 보정창 점수 최대값+0.01 정책을 적용했고, 평가 결과를 보고 이를 바꾸지 않았다.

학습한 모델을 고정한 뒤 `data/random.json`의 별도 녹화 48개 창에 적용했다. 이 자료는 앞서 팀이 이미 확인한 녹화이므로 새로운 미공개 테스트라고 주장하지 않으며 탐색적 재사용이다.

## 실제 결과

| 명령 자극 | 평가 창 | 참조 이탈로 판정 | 해석 |
|---|---:|---:|---|
| 기준 연속 진동 | 12 | 3 | 기준 명령인데 이탈로 판정. 오경보 또는 참조 분포 변화 검토 필요 |
| 무진동 | 12 | 12 | 운전 참조와 다른 자극을 포착. 실제 장비에서는 운전/정지 조건도 구분해야 함 |
| 강한 연속 진동 | 12 | 0 | 이번 참조 변화 시험에서 전부 놓침 |
| 간헐 진동 | 12 | 12 | 참조와 다른 시간 패턴을 포착 |

경계는 약 0.5376648이다. 이 숫자는 이 후보의 점수 경계이며 g 단위도 고장 확률도 아니다.

**이 후보를 실제 발전기 이상탐지 모델로 채택할 근거는 부족하다.** 자동 적용하지 않고, 제공 녹화용 후보의 실물 적용 자체를 코드에서 차단했다. 기존 네 패턴 분류기의 48/48을 이 모델의 정확도로 대체하지 않는다. 기존 분류기 JSON은 변경하지 않았다.

## 자료의 한계

- 실제 발전기가 아닌 아이폰–IMU 실험이다. 명령 자극이 정답이며 기계 고장 정답이 아니다.
- 기준 진동 12개 창뿐이고 학습/보정은 한 녹화 내부다. 정상적인 환경 변동을 대표한다고 볼 수 없다.
- 무작위 녹화의 기준 진동 RMS가 앞선 녹화보다 낮았다는 원본 보고의 관찰을 유지하며 원인을 새로 단정하지 않는다.
- 센서 풀스케일이 원본 CSV에 없으므로 새로 포화가 없었다고 인증하지 않는다.
- 이번 평가는 알려진 자극 구간 안의 창이다. 전환이 포함된 전체 연속 스트림 성능은 아니다.

## 배포 코드와 성능을 구분

온디바이스에서 후보를 학습·저장하고 JSON 모델로 추론하는 경로는 구현했다. 새 설치의 참조 기록 승인, 세션 분리, 모델 버전 관리, 후보 검토를 거치도록 했다. 실제 발전기 모델은 해당 장비의 서로 다른 승인된 운전과 새로운 평가 기록으로 검증해야 한다.

`verification/ml/host-validation/verification.json`의 시간·메모리는 **Linux x86_64 호스트** 측정이다. UNO Q 성능 수치가 아니다. `Deploy-and-Verify.command`가 실행된 후 보드에서 생성된 보고서만 보드 실행의 근거로 사용한다.
